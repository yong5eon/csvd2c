# 요구사항

## 분석

- GitHub 에이전트는 대상 저장소를 기준으로 작업하므로 로컬 개발환경의 공통 지침 링크에 의존할 수 없다.
- 저장소의 프로젝트별 지침은 추적되지만 공통 지침은 각 저장소의 일반 작업 파일로 제공되지 않았다.
- `.github/workflows/ci.yml`은 PR 브랜치명을 사용해 `issues/{branch}/CHANGELOG.md`를 찾고, 파일이 없거나 비어 있으면 실패한다.
- 따라서 AGENTS 진입 문서와 추적 가능한 공통 지침 사본을 추가하고, CI가 읽는 이슈별 변경 로그를 작성해야 한다.

## 초기 확정 요구사항

- 루트 `AGENTS.md`는 작업 전 공통 지침과 적용 가능한 csvd2c 지침을 읽도록 한다.
- 공통 지침 사본은 `instructions/common/`에 두고 원본 `yong5eon/Instructions`의 커밋 `8706862712c800682f38af3c86e74f768345d811`에서 복사한다. 커밋 메시지 전용 지침은 제외한다.
- `AGENTS.md`는 승인 범위, 이슈 작업, 작업 판단 기록, 검증과 `issues/task/16/CHANGELOG.md` 확인을 안내한다.
- 제품 소스·공개 API 변경은 제외한다.

## 초기 인수 기준

- AGENTS에서 링크한 다섯 공통 지침 파일과 프로젝트별 지침 파일이 실제 경로에 존재한다.
- 공통 파일이 지정한 원본 커밋과 동일하며 커밋 메시지 전용 지침은 포함하지 않는다.
- 이슈별 `CHANGELOG.md`가 일반 파일이며 비어 있지 않다.
- CI가 기대하는 경로가 브랜치 `task/16`의 `issues/task/16/CHANGELOG.md`와 일치한다.

## 후속 사용자 결정

- 초기 이슈 원문과 달리 커밋 메시지 지침을 포함한다. 이후 사용자 결정에 따라 공통 에이전트 지침은 `.instructions.assistant/`, csvd2c 전용 지침은 `.instructions/`로 구분하고 두 위치를 `AGENTS.md`에서 안내한다.
- 이슈 유무에 관계없이 요구사항, 계획, 변경 로그와 단계별 기록을 작성한다. 구현이 있으면 `IMPLEMENTS.md`, 구현 외 작업이 있으면 `TASKS.md`도 작성한다.
- 이슈가 없는 작업은 요청과 작업 범위를 `README.md`에 먼저 기록하고 조사·분석 결과로 보강한다. 조사·분석은 모든 실제 작업에서 작업 내용과 위험에 맞는 범위로 수행한다.
- 원격 플랫폼이 제공한 브랜치와 이슈 유형·번호를 기준으로 한 기록 경로를 구분한다. 중요한 미확정 사항은 임의로 구현하지 않고 필요한 결정을 기록한다.
- 이슈 PR 본문 마지막에 `- Changes: issues/<레이블>/<이슈번호>/CHANGELOG.md` 형식의 경로를 명시한다.
- 단독 커밋에는 작성자 본인을 공동 기여자로 적지 않는다. 공동 기여자가 있으면 실제 확인된 작성자 외 기여자를 `Co-authored-by`로 표시한다.
- 커밋 메시지 지침은 메시지 작성에 필요한 내용으로 유지하고 VS Code 전용 설정 설명과 불필요한 중복을 제거한다.
- 나머지 공통·프로젝트 지침도 에이전트의 작업에 필요한 계약과 예외는 보존하면서 불필요한 내용과 중복을 제거한다.
- 단순 의견·설명 요청과 자료 확인이 필요한 검수 요청을 구분한다. 검수에 필요한 읽기 전용 조사는 허용하되 파일 수정이나 외부 시스템 변경의 허가로 확대하지 않는다.
- 코드 변경 시 상세 매뉴얼과 루트 README의 영향 여부를 확인하고 필요한 갱신 또는 불필요한 이유를 기록한다.
- 비코드 작업을 포함한 계획에는 해당 작업에 실제로 적용되는 대상과 역할을 기록한다. 필수 요구사항·계획 문서는 유지한다.
- 상세 매뉴얼 지침의 한·영 동시 갱신 문장을 사용자가 원복한 사실과 그에 관한 에이전트의 잘못된 설명을 기존 기록을 보존하면서 정정한다.
- 당시 지침 정리 범위에는 CI 변경을 포함하지 않았다. 당시 CI는 PR 본문의 경로가 아닌 브랜치명으로 변경 로그를 찾아 원격 브랜치에서 초기 이슈의 CI 일치 인수 기준이 미충족이었다.
- 원격 에이전트가 `AGENTS.md`를 통해 두 지침 디렉터리를 읽는다고 가정한다. 실제 GitHub 실험은 사용자가 추후 수행한다.
- 기존 이슈 브랜치의 PR 자동 생성에서 이슈 종료 구문을 유지하고 본문 마지막에 `- Changes: issues/<유형>/<번호>/CHANGELOG.md`를 기록한다.
- 당시 결정으로 새 PR을 생성할 때 변경 로그가 없거나 공백뿐이면 명시적인 오류로 생성을 중단하고, 이미 열린 PR의 본문은 수정하지 않았다.
- 당시 PR 본문 변경에는 CI의 변경 로그 수집 방식 변경을 포함하지 않았다.
- 후속 CI 작업에서는 PR 본문의 `Changes:` 경로를 우선 사용하고, 해당 항목이 없는 기존 PR은 브랜치 기반 경로를 유지한다.
- 이슈 작업의 `issues/<유형>/<번호>/CHANGELOG.md`와 비이슈 작업의 `tasks/<UNIX_TIMESTAMP>/CHANGELOG.md`만 명시 경로로 허용한다. 당시에는 본문 전체에서 잘못된 항목이나 중복 항목을 오류로 처리했다.
- 비이슈 작업의 PR 작성·갱신 지침에도 `Changes:` 경로를 명시한다. `master` 직접 push와 기존 릴리즈 노트 재사용 동작은 유지한다.
- 릴리즈 노트 수집 테스트 파일은 변경 시 수동 검증용으로 유지하고 CI의 자동 실행 단계는 제거한다.
- 완료·중단된 단계별 기록은 후속 작업에 맞춰 수정하지 않고, 정정과 후속 결과는 이전 기록을 연결한 새 기록으로 남긴다. 진행 중인 작업 단위의 기록과 현재 상태·종합 문서의 갱신은 구분한다.
- csvd2c 공통 지침과 개인적으로 관리하는 Instructions 지침에 이 원칙을 명시한다. Instructions에는 별도 작업 기록을 남기지 않고 `master`에서 작업한다.
- 이슈 브랜치 자동화가 새로 생성하는 PR은 Draft로 시작한다. 이미 열린 PR의 상태와 기존 동기화 동작은 변경하지 않는다.
- 이후 사용자는 열린 PR이 있으면 푸시된 최신 작업 문서로 제목과 본문 전체를 갱신하기로 결정했다. 수동으로 수정한 제목·본문도 덮어쓰며, 변경 로그가 없거나 공백뿐이면 오류로 갱신하지 않는다. Draft 상태는 변경하지 않는다.
- 이후 사용자는 작업 문서를 `<details>` 없이 PR 본문에 표시하고, CI는 마지막 비어 있지 않은 줄의 `Changes:`를 경로로 사용하도록 결정했다. 바로 앞의 비어 있지 않은 줄에 인접한 중복 항목이 있으면 오류로 처리한다.
- 마지막 줄에 `Changes:` 항목이 없으면 기존 브랜치 경로로 폴백한다. 따라서 마지막이 아닌 항목은 실제 경로로 인식하지 않고, 본문 끝이 우연히 같은 형식의 문서 예시인 기존 PR은 구분할 수 없다는 한계를 수용한다.
- 이후 사용자는 푸시 시 AI가 기존 작업 내용을 요약해 PR 템플릿에 맞는 간결한 본문을 작성하도록 요청했다. 별도의 `PR.md`나 에이전트 작성 지침은 요구하지 않는다.
- 당시에는 PR 요약에 기존 리뷰 처리와 동일한 Copilot CLI 기본 모델 설정을 사용하기로 했다. 이후 아래 `PR.md` 방식으로 변경되어 적용하지 않는다.
- 이후 사용자는 AI 자동 요약 대신 이슈 작업 디렉터리의 `PR.md`를 PR 템플릿에 맞춰 직접 작성하고 푸시 자동화가 이를 사용하도록 변경했다. 사람과 에이전트의 이슈 작업에 적용하며 비이슈 작업에는 요구하지 않는다.
- 사용자는 `PR.md`에 작성한 제목도 PR 제목으로 사용하도록 요청했다.
- 이후 사용자는 GitHub PR과 GitLab MR을 포괄하도록 파일 이름을 `IR.md`로 바꾸고 현재 템플릿 내용을 공통 지침에 직접 넣어 특정 템플릿 파일에 의존하지 않도록 요청했다.
- 사용자는 `IR.md`에도 이슈 종료 구문과 변경 로그 경로를 직접 포함하도록 요청했다.
- 사용자는 두 항목을 `관련 이슈 및 변경 로그` 섹션으로 구분하도록 요청했다.
- 사용자는 여러 이슈를 `Closes`에 작성할 수 있도록 하고 `Changes:`는 비어 있지 않은 마지막 줄만 검사하도록 요청했다.
- 사용자는 `copilot/**`, `codex/**` 브랜치의 기존 PR에서 변경된 이슈 `IR.md`를 찾아 제목과 본문을 갱신하도록 요청했다. 이슈 #16이 종료된 상태에서 `task/16`의 기존 기록을 이어서 사용하기로 했다.
- `REQUIREMENTS.md`, `CHANGELOG.md`와 존재하는 `IMPLEMENTS.md`, `TASKS.md`를 근거로 변경 내용과 실제 검증 결과를 간결하게 작성한다. 작업 문서의 전체 내용을 자동으로 붙이지 않는다.

## 이번 후속 작업의 인수 기준

- 단순 질문·의견은 답변만 하고, 명시적인 검수 요청은 필요한 읽기 전용 확인을 수행하며 수정 권한을 추정하지 않는다.
- 코드 작업에서 상세 매뉴얼과 루트 README의 영향 확인, 필요한 갱신 및 변경이 불필요한 경우의 이유 기록을 안내한다.
- 계획에 작업에 해당하는 대상·역할을 기록하되 모듈·클래스·함수가 없는 작업에 해당 항목을 강제하지 않는다.
- 한국어·영어 매뉴얼 작성·갱신 규칙과 필수 작업 문서·단계별 기록 규칙을 유지한다.
- 기존 정리 기록은 보존하고 원복과 에이전트 설명 오류를 후속 기록에 남긴다. 변경 지침의 연결과 각 인수 기준을 확인한다.

## PR 본문 변경의 인수 기준

- 새 PR의 마지막 비어 있지 않은 줄은 `- Changes: issues/<유형>/<번호>/CHANGELOG.md`다. 여러 이슈의 종료 구문을 앞에 작성할 수 있다.
- 변경 로그가 누락되거나 공백뿐이면 PR 생성 요청 전에 오류를 반환한다. 그 밖의 문서나 템플릿 누락은 기존 동작을 유지한다.
- 당시에는 이미 열린 PR의 메타데이터만 동기화하고 본문을 변경하지 않았다. 이후 열린 PR의 제목·본문도 갱신하도록 요구사항이 변경됐다.
- 이슈 종료 연결과 65,536자 제한을 관련 테스트로 확인한다. 이후 `PR.md` 방식에서는 제한 초과 시 링크로 대체하지 않고 실패한다.

## CI 변경 로그 경로의 인수 기준

- 새 버전 릴리즈의 병합 PR에서 유효한 `Changes:`를 우선 적용하고, 항목이 없는 기존 PR은 기존 브랜치 경로를 사용한다.
- 이슈·비이슈 경로 모두 병합 결과의 일반 파일이어야 하며 비어 있으면 실패한다. 마지막 항목의 허용 범위 밖 경로·잘못된 형식은 오류로 처리한다.
- 마지막 비어 있지 않은 줄보다 앞선 항목은 해석하지 않는다. 마지막 줄에 나타난 항목은 본문 예시와 구분할 수 없다.
- PR이 없는 직접 push와 기존 릴리즈 노트 재사용 동작을 보존한다.
- 이슈가 없는 작업의 PR에도 `tasks/<UNIX_TIMESTAMP>/CHANGELOG.md` 경로를 마지막에 기록하도록 안내한다.

## 기존 PR 갱신의 인수 기준

- 새 PR과 같은 브랜치의 열린 PR은 푸시된 `IR.md`의 첫 줄 제목과 나머지 본문을 사용한다. 기존 PR의 수동 수정은 보존하지 않는다.
- 변경 로그가 누락되거나 공백뿐이면 원격 쓰기 전에 오류를 반환한다. 갱신 API 오류도 전파한다.
- PR의 Draft 상태는 변경하지 않고 기존 메타데이터·이슈 연결 동기화와 새 PR 생성 동작을 유지한다.
- `IR.md`가 없거나 공백뿐이면 원격 쓰기 전에 오류를 반환한다.
- `IR.md`의 첫 줄은 비어 있지 않은 256자 이하의 Markdown 최상위 제목이며, 그 아래에 비어 있지 않은 본문이 있어야 한다. 제목이 없거나 유효하지 않으면 원격 쓰기 전에 오류를 반환한다.
- 공통 지침에 제목과 기존 템플릿의 변경 내용·유형·검증·확인 사항을 포함하고 특정 플랫폼의 템플릿 파일을 지정하지 않는다. 이슈 작업에 적용하며 비이슈 작업에는 추가하지 않는다.
- csvd2c 이슈 작업의 `IR.md`는 실제 해결한 이슈의 종료 구문과 마지막 비어 있지 않은 줄에 `- Changes: issues/<유형>/<번호>/CHANGELOG.md`를 포함한다. 자동화는 마지막 줄만 검증하고 항목을 중복 추가하지 않는다.

## 에이전트 브랜치 PR 갱신

- `copilot/**`, `codex/**`의 푸시도 워크플로 실행 대상으로 한다. 기존 이슈 브랜치 동작은 유지한다.
- 에이전트 브랜치는 열린 PR의 전체 변경 파일에서 삭제되지 않은 `issues/<유형>/<번호>/IR.md`를 찾고 해당 문서로 제목과 본문을 갱신한다. PR이 아직 없으면 생성하지 않고 건너뛴다.
- 문서가 없거나 여러 개이거나 변경 파일 목록을 온전히 확인할 수 없으면 원격 쓰기 전에 오류를 반환한다.
- 에이전트 PR은 제목·본문만 갱신하며 레이블·담당자·마일스톤과 이슈 연결은 변경하지 않는다. 에이전트의 이후 본문 변경을 방지하거나 작업 완료 시점을 보장하지 않는다.

## PR 리뷰 후속 수정

- 마지막 `Changes:` 목록 항목 앞에 공백이 1~3칸 있으면 유효한 경로로 취급하거나 브랜치 경로로 대체하지 않고 오류로 처리한다.
- 네 칸 이상이나 탭으로 들여쓴 마지막 줄은 기존처럼 코드 예시로 취급해 브랜치 경로로 폴백한다. 이 방식은 같은 들여쓰기의 중첩 목록과 코드 예시를 구분하지 않는다.
- PR 생성·갱신 시 변경 로그가 비어 있지 않은 일반 파일인지 확인하고 심볼릭 링크는 거부한다.
- 정상 항목, 일반 파일과 기존 오류 처리 동작을 유지한다. 파일 3,000개 제한과 App 권한 구조 변경은 제외한다.
