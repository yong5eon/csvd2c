# CI 변경 로그 경로 테스트 및 검증

- 실제 워크플로의 릴리즈 노트 수집 코드를 실행하는 표준 라이브러리 테스트를 준비했다.
- 이슈·비이슈 명시 경로, 이전 브랜치 경로, 잘못된 항목과 중복, 문서 발췌·코드 예제, 파일 오류, 직접 push 및 릴리즈 재사용을 확인한다.
- [관련 근거](../context/1794057719626.md)에 따라 변경 전 실패와 구현 후 결과를 기록한다.
- 변경 전 `python -S -m unittest discover -s .github/scripts/tests -p test_release_notes.py -k explicit -v`를 실행했다. 이슈·비이슈 명시 경로 두 경우 모두 기존 코드가 원격 브랜치 기반 경로를 사용해 실패했다.
- 구현 중 PR 주석과 들여쓰기 코드의 예시를 추가해 `-k document_details` 테스트를 실행하자 예시를 중복 항목으로 잘못 인식하는 실패가 발생했다. 실제 항목과 구분하도록 처리했다.
- 변경 후 `python -S -m unittest discover -s .github/scripts/tests -p test_release_notes.py -v`에서 7개 테스트가 통과했다. 예시만 있는 경우에도 기존 경로로 폴백하는 동작을 포함한다.
- 기존에 설치된 PyYAML로 워크플로 YAML 구문과 `changes` 작업을 확인했고, Pylance에서 테스트 파일의 구문 오류와 진단이 없었다. 로컬 Python은 3.14이며 CI는 3.13을 사용한다.
- 변경 범위는 저장소의 PR·릴리즈 자동화로, 제품 API·설치·사용법을 다루는 상세 매뉴얼과 루트 README의 갱신은 불필요하다.
- 변경 기록 문서 9개의 상대 링크 46개, 개인 절대 경로와 줄 끝 공백을 확인했다. 최초 검사에서 URL의 `s:/`를 드라이브 경로로 잘못 판정해 검사식을 바로잡고 다시 통과했다. `git diff --check`도 통과했다.
- 실제 GitHub Actions 실행, PR 생성·수정과 배포는 수행하지 않았다. 로컬 모의 테스트가 실제 원격 실행을 보장하지는 않는다.
