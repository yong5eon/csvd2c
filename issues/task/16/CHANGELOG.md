# PR 자동 생성

- 이슈 브랜치에서 새로 생성하는 PR은 본문 마지막에 이슈 종료 구문과 이슈별 `CHANGELOG.md` 경로를 표시합니다.
- 변경 로그가 없거나 공백뿐이면 새 PR을 생성하지 않습니다. 이슈별 변경 로그를 작성한 뒤 브랜치에 반영해야 합니다.
- 이미 열린 PR의 본문은 자동으로 변경하지 않습니다.

## 릴리즈 변경 로그 수집

- 새 버전 릴리즈에서 병합 PR 본문의 `- Changes: <경로>`로 이슈 작업의 `issues/<유형>/<번호>/CHANGELOG.md` 또는 비이슈 작업의 `tasks/<UNIX_TIMESTAMP>/CHANGELOG.md`를 지정할 수 있습니다. 지정한 경로를 브랜치 이름보다 우선합니다.
- 항목이 없는 기존 PR은 이전처럼 브랜치 기반 경로를 사용합니다. 경로가 잘못되었거나 항목이 중복되면 릴리즈 작업이 실패하므로 PR 본문과 변경 로그 파일을 확인해야 합니다.
- `master` 직접 push와 기존 릴리즈 노트 재사용 방식은 유지됩니다.

csvd2c의 런타임 동작, 공개 API와 설치 방법은 변경되지 않습니다.
