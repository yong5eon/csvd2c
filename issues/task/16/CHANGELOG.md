# PR 자동 생성

- 이슈 브랜치에서 자동으로 생성하는 새 PR은 Draft로 시작합니다. 준비가 되면 GitHub에서 일반 PR로 전환해야 합니다.
- 이슈 브랜치에서 생성·갱신하는 PR은 `IR.md`의 이슈 종료 구문과 마지막 줄의 이슈별 `CHANGELOG.md` 경로를 사용합니다. 실제 해결한 이슈가 여러 개면 각각 `Closes`를 작성할 수 있습니다.
- 이슈 작업자는 작업 디렉터리의 `IR.md` 첫 줄에 `# PR 제목`을 작성하고 그 아래에 공통 작업 지침의 형식에 맞는 본문을 작성합니다. 푸시 시 이 파일의 제목과 본문을 사용합니다.
- 같은 브랜치에 열린 PR이 있으면 `IR.md`의 제목과 본문으로 전체를 갱신합니다. **직접 수정한 제목과 본문도 덮어쓰므로** 보존할 내용은 `IR.md`에 반영해야 합니다.
- 변경 로그나 유효한 제목·본문·마지막 항목이 있는 `IR.md`가 없으면 새 PR을 생성하거나 기존 PR을 갱신하지 않습니다. 기존 이슈 브랜치도 두 파일과 이슈에 맞는 마지막 항목을 작성한 뒤 푸시해야 하며 `PR.md`는 자동화 입력으로 사용하지 않습니다. 제목은 256자 이하여야 하며 PR 본문이 65,536자를 넘으면 내용을 줄여야 합니다.
- 이미 열린 PR의 Draft 상태는 자동으로 변경하지 않습니다.

## 릴리즈 변경 로그 수집

- 새 버전 릴리즈에서 병합 PR의 마지막 비어 있지 않은 줄에 `- Changes: <경로>`를 작성하면 이슈 작업의 `issues/<유형>/<번호>/CHANGELOG.md` 또는 비이슈 작업의 `tasks/<UNIX_TIMESTAMP>/CHANGELOG.md`를 브랜치 이름보다 우선합니다.
- 마지막 줄에 항목이 없는 기존 PR은 이전처럼 브랜치 기반 경로를 사용합니다. 마지막이 아닌 항목은 인식하지 않습니다. 마지막 항목의 형식·경로가 잘못되면 릴리즈 작업이 실패합니다.
- 마지막 줄의 일반 텍스트 예시가 실제 항목과 같으면 구분할 수 없으므로 PR을 작성할 때 본문 끝을 확인해야 합니다. 네 칸 이상 들여쓰거나 탭으로 시작하는 줄은 항목으로 취급하지 않습니다.
- `master` 직접 push와 기존 릴리즈 노트 재사용 방식은 유지됩니다.

## 작업 기록 보존

- 완료하거나 중단한 단계별 기록은 후속 작업에 맞춰 변경하지 않고, 정정과 후속 결과는 이전 기록을 연결한 새 기록에 남깁니다.
- 진행 중인 작업 단위의 기록과 현재 상태·종합 문서는 필요한 범위에서 갱신할 수 있습니다.

csvd2c의 런타임 동작, 공개 API와 설치 방법은 변경되지 않습니다.
