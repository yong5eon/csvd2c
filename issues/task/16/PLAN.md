# 작업 계획

## 초기 수행 및 상태

1. `task/16` 브랜치, 이슈 라벨, 프로젝트별 지침과 changelog CI 경로를 확인 — 완료
2. 공통 지침 다섯 파일을 `instructions/common/`에 원본 커밋 기준으로 복사 — 완료
3. 루트 `AGENTS.md`에 지침 진입·작업 범위·이슈별 changelog 규칙을 작성 — 완료
4. 이슈별 작업·구현 기록과 고객용 변경 로그 작성 — 완료
5. 파일 경로·내용 동기화·CI changelog 경로를 로컬에서 검증 — 완료
6. 실제 GitHub Codex·Copilot 세션에서 지침 로드를 확인 — 저장소에 반영된 뒤 수행 필요

제품 동작은 변경하지 않는다. 커밋·푸시·PR은 별도 요청이 없어 수행하지 않는다.

## 후속 작업

1. 기존 기록과 원본 이슈를 대조하고 비이슈 작업으로 잘못 분류한 기록을 이슈 기록으로 정정 — 완료
2. CLI·원격 에이전트에 맞는 통합 지침, 이슈 유무 공통 작업 기록과 트레일러 기준 정리 — 완료
3. 이슈 문서와 보존 기록의 상대 링크, 지침과 실제 결과를 검증 — 완료
4. 비이슈 작업의 요청 기록과 필수 조사·분석 흐름을 작업 지침에 반영하고 확인 — 완료
5. 공통 지침을 `.instructions.assistant/`로 이동하고 `AGENTS.md` 및 관련 링크를 갱신한 뒤 경로와 기존 연결을 확인 — 완료
6. 커밋 메시지 지침에서 VS Code 전용 설정과 중복 설명을 정리하고 필수 작성 규칙을 확인 — 완료
7. 나머지 공통·프로젝트 지침을 검토하고 중복이나 불필요한 내용을 정리한 뒤 필수 규칙을 확인 — 완료
8. 검수 권한, 코드 작업의 문서 영향 검토, 비코드 작업 계획 기준과 이전 판단 정정 — 완료
9. 기존 PR 자동 생성의 이슈 종료 구문을 유지하면서 변경 로그 경로를 마지막에 기록 — 완료
10. 기존 경로를 유지하면서 이슈·비이슈 PR의 변경 로그 경로를 CI에서 수집 — 구현 및 로컬 검증 완료
11. 릴리즈 노트 수집 테스트의 CI 실행 단계 제거 — 완료
12. 완료·중단된 단계별 기록의 보존 원칙 명확화 — 완료

### 후속 작업 8의 변경·검증 계획

1. `INSTRUCTIONS.instructions.md`에서 단순 의견과 자료 확인이 필요한 검수를 구분하고, 검수만으로 파일 수정·외부 변경이 허용되지 않음을 명시한다.
2. `AGENTS.md`의 코드 작업 안내에서 상세 매뉴얼과 루트 README 지침으로 연결하고, 영향 확인·필요한 갱신·불필요한 이유 기록을 안내한다.
3. `TASK.instructions.md`의 주요 작업 계획 항목을 실제 작업에 해당하는 대상·역할로 표현해 비코드 작업에 코드 구성요소를 강제하지 않는다.
4. 기존 기록을 보존하고 사용자의 한·영 지침 원복과 에이전트의 잘못된 설명을 후속 근거·작업 기록에 정정한다.
5. 각 지침의 적용 범위와 필수 규칙, 변경한 문서의 상대 링크를 확인한다. 문서만 변경하므로 제품 테스트는 실행하지 않는다.

PR 본문 경로를 CI가 읽도록 구현하고 로컬에서 검증했다. 실제 GitHub Actions와 에이전트 세션 검증은 수행하지 않았다.

### 후속 작업 9의 변경·검증 계획

1. `.github/scripts/create-pr-from-issue.mjs`의 `createPullRequest`가 새 PR 생성 전에 읽은 변경 로그의 누락·공백 여부를 검사해 실패를 명시한다. 이미 열린 PR의 처리 분기는 변경하지 않는다.
2. `buildPullRequest`의 모든 본문 생성 경로에서 `Closes`와 `Changes:`를 마지막 두 목록 항목으로 작성한다. 기존 길이 제한 계산에 이 항목을 포함한다.
3. `.github/scripts/tests/create-pr-from-issue.test.mjs`에서 정상·누락·빈 변경 로그, 기존 PR 본문 보존, 본문 크기 경계와 링크 대체 경로를 검증한다.
4. 상세 매뉴얼과 루트 README의 영향 여부를 판단하고 실제 결과를 이슈 기록과 변경 로그에 남긴다. CI 변경과 실제 GitHub PR 생성·수정은 이번 범위가 아니다.

### 후속 작업 10의 변경·검증 계획

1. `AGENTS.md`와 `TASK.instructions.md`에 이슈가 없는 PR도 실제 변경 로그 경로를 마지막에 작성하도록 명시한다.
2. `.github/workflows/ci.yml`의 릴리즈 노트 수집 단계에서 병합 PR 본문의 유효한 `Changes:`를 우선 적용한다. PR에 항목이 없으면 기존 브랜치 경로를 사용하고, 직접 push와 기존 릴리즈 재사용 분기는 그대로 둔다.
3. 명시된 경로의 허용 형식과 항목 중복을 검사한 뒤 기존 Git 트리의 일반 파일·비어 있지 않음 검증을 적용한다. 문서 발췌와 코드 예제는 PR 본문의 실제 항목과 구분한다.
4. 워크플로의 실제 수집 코드를 표준 라이브러리 모의 테스트로 실행해 두 명시 경로, 기존 경로, 잘못된 입력, 파일 오류, 직접 push 및 릴리즈 재사용을 확인한다. 당시 CI에도 테스트를 추가했으며 후속 작업 11에서 제거한다.
5. 사용자용 매뉴얼과 루트 README의 영향 여부를 검토하고 변경 로그와 작업 기록을 갱신한다. 실제 GitHub PR 생성·수정과 배포는 수행하지 않는다.

### 후속 작업 11의 변경·검증 계획

1. `.github/workflows/ci.yml`에서 릴리즈 노트 수집 테스트 실행 단계만 제거하고 테스트 파일과 릴리즈 수집 단계는 유지한다.
2. 워크플로 YAML 구문과 단계 구성을 확인하고 변경된 작업 기록을 정리한다. 수집 코드와 테스트 파일은 변경하지 않으므로 테스트 재실행은 생략한다.

### 후속 작업 12의 변경·검증 계획

1. csvd2c의 `task/16`에서 `.instructions.assistant/TASK.instructions.md`를, Instructions의 `master`에서 `TASK.instructions.md`를 수정한다. Instructions는 별도 이슈와 작업 기록 없이 사용자가 직접 관리한다.
2. 단계별 기록은 작업 단위의 완료·중단 이후 보존하고 후속 정정은 새 기록에 남기도록 명시한다. 진행 중 갱신과 현재 상태·종합 문서는 구분하고 승인된 민감정보 정리 규칙은 유지한다.
3. 두 지침의 해당 원칙이 일치하는지 확인하고 csvd2c의 작업 결과를 새 단계별 기록과 종합 문서에 남긴다. 문서 변경이므로 제품 테스트는 실행하지 않는다.
