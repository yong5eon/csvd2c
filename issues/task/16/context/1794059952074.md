# PR 문서 표시와 footer 경로 처리

## 상황과 근거

[PR #23의 미해결 리뷰](https://github.com/yong5eon/csvd2c/pull/23#discussion_r4501960580)는 작업 문서 속 `<details>` 태그가 CI의 문서 경계 판별을 혼동한다고 지적했다. 실제 생성기는 문서를 `<details>`로 포장하고, CI는 본문 전체의 태그 깊이와 `Changes:` 항목을 해석한다.

사용자는 문서 포장을 제거하고 본문 끝의 두 줄을 기준으로 처리하는 방식을 선택했다. 이슈 PR은 기존대로 `Closes` 다음에 `Changes:`를 두며, 비이슈 PR은 `Changes:`만 둘 수 있다.

## 결정과 영향

마지막 비어 있지 않은 줄이 `Changes:`이면 해당 경로를 사용하고, 바로 앞의 비어 있지 않은 줄이 같은 항목이면 중복으로 실패한다. 마지막에 항목이 없으면 기존 브랜치 경로를 사용한다. 이전의 본문 전체 검사와 마지막이 아닌 항목의 인식은 중단한다.

이 방식은 문서의 HTML을 해석하지 않지만 본문 끝이 우연히 항목과 같은 예시인 경우 예시와 실제 항목을 구분하지 못한다. 문서 표시에서는 원문 링크와 PR 길이 제한에 따른 링크 폴백을 보존한다.

기존 들여쓰기 코드 예시 처리와 호환되도록 네 칸 이상 들여쓰거나 탭으로 시작하는 마지막 줄은 항목으로 취급하지 않는다. 실제 GitHub Actions 실행은 확인하지 않았다.
