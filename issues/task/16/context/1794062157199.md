# 이슈 PR 본문 작성 방식 변경

## 상황과 근거

기존 자동화는 작업 문서 전문을 PR에 표시해 본문이 길어졌다. 사용자는 변경 로그, 요구사항 및 존재하는 구현·작업 종합 문서를 근거로 PR 템플릿에 맞는 `PR.md`를 작성하고 푸시 시 이를 사용하기로 했다.

사용자는 이 프로젝트에서 이 규칙을 에이전트에만 한정하지 않고 이슈 작업에 적용하며, 비이슈 작업에는 요구하지 않기로 했다. 앞선 자동 AI 요약 계획은 이 결정으로 대체한다.

에이전트는 앞서 자동 요약 가능 여부에 관해 일관되지 않게 설명하고 불필요한 확인을 반복했다. 사용자는 그 대신 작업자가 로컬에서 PR 본문을 작성하는 방식을 선택했다.

## 결정과 영향

`PR.md`를 이슈 디렉터리에 두고 변경 내용과 실제 검증을 간결하게 작성한다. 푸시 자동화는 본문과 footer를 결합하며 기존 제목·Draft 및 기존 PR 갱신을 유지한다. `PR.md`가 없거나 비어 있으면 다른 문서로 대체하지 않고 오류를 표시한다.

기존 이슈 브랜치에는 `PR.md`가 없을 수 있으므로 해당 브랜치에서 자동 PR을 생성하거나 갱신하기 전에 파일을 작성해야 한다. 길이 제한을 넘는 본문은 임의로 자르지 않고 오류로 처리한다.

관련 Node 테스트 58개가 통과했다. 실제 GitHub Actions와 PR 생성·갱신은 검증하지 않았다.
