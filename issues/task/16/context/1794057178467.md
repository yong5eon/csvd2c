# PR 변경 로그 검증과 기존 본문 처리 결정

## 상황과 근거

[기존 동작 조사](./1794057075718.md)에서 변경 로그 누락과 기존 PR 본문의 처리 방식이 미확정이었다. 사용자는 변경 로그가 없거나 비어 있으면 새 PR 생성을 중단하고, 이미 열린 PR의 본문은 유지하도록 선택했다.

## 결정과 영향

새 PR 생성 분기에서 변경 로그를 확인한 다음 본문을 생성하고 API를 호출한다. 누락·빈 파일을 허용하던 기존 동작은 사용자 결정에 따라 변경되지만 다른 문서·템플릿의 기존 선택적 처리는 유지한다. 이미 열린 PR의 분기는 변경하지 않는다.

본문 생성 시 `Closes`와 `Changes:`를 마지막에 추가해 이슈 종료 구문과 변경 로그 경로를 함께 제공한다. 본문 길이 제한을 적용하기 전에 두 항목을 포함해 기존 경계 검증이 실제 결과를 대상으로 하게 한다. CI의 수집 방식 변경과 실제 PR 수정은 수행하지 않는다.
