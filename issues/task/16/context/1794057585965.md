# CI 변경 로그 경로 수집 분석

## 상황과 근거

사용자는 기존 브랜치 기반 규칙을 유지하면서 PR의 `Changes:`로 이슈·비이슈 작업의 변경 로그를 식별하도록 요청했다. 현재 `.github/workflows/ci.yml`은 `master` push에서 병합 PR을 찾고, 새 버전일 때 PR 브랜치로 `issues/<브랜치>/CHANGELOG.md`를 읽는다. 직접 push와 기존 릴리즈 노트 재사용은 별도 분기다.

이슈 PR 자동 생성은 작업 문서를 PR의 `<details>`에 포함하므로, 본문 전체에서 `Changes:` 문자열만 검색하면 문서 속 예시를 실제 항목으로 잘못 인식할 수 있다. 에이전트 진입 지침은 이슈 PR 경로만 명시한다.

## 결정과 영향

PR 본문의 실제 목록 항목에서 허용된 경로 하나를 찾고, 문서 발췌나 코드 예제와 구분한다. 유효한 명시 경로가 있으면 우선 사용하고 항목이 없으면 기존 브랜치 경로를 유지한다. 잘못된 형식이나 중복은 폴백하지 않고 오류로 처리한다. 기존 Git 트리의 파일 유형과 내용 검증, 직접 push와 기존 릴리즈 재사용은 유지한다.

비이슈 PR의 경로 작성은 진입 지침과 작업 지침에 연결한다. 실제 워크플로 수집 코드를 모의 GitHub·Git 응답으로 검증하며 외부 시스템은 변경하지 않는다.
