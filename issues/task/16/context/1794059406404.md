# 열린 PR의 제목과 본문 갱신

## 상황과 근거

이슈 브랜치 push에서 기존 열린 PR을 찾으면 현재는 본문을 읽거나 갱신하지 않고 레이블·담당자·마일스톤·이슈 연결만 동기화한다. 사용자는 푸시할 때 최신 작업 내용으로 PR을 갱신하도록 요청했다.

기존 본문에는 수동 편집이 있을 수 있으므로 사용자에게 처리 방식을 확인했다. 사용자는 제목도 갱신하고, 본문은 전체를 교체하며, 변경 로그가 없거나 비어 있으면 오류 처리하도록 결정했다.

## 결정과 영향

새 PR과 동일한 `buildPullRequest`로 푸시된 작업 문서와 템플릿에서 제목·본문을 생성하고 기존 PR을 갱신한다. 제목과 본문의 수동 변경은 덮어쓰며 Draft 상태는 그대로 둔다. 변경 로그 오류는 원격 쓰기 전에 보고한다.

[GitHub의 PR 수정 API 문서](https://docs.github.com/en/rest/pulls/pulls#update-a-pull-request)는 `PATCH` 요청의 `title`과 `body`를 지원한다. 모의 테스트만으로 실제 GitHub Actions 실행을 보장하지는 않는다.

기존 생성기와 같은 문서 처리·검증을 재사용하고 PR 수정 API에는 제목과 본문만 전달했다. 변경 후 PR 자동화 테스트 64개가 통과했다.
