# 여러 이슈 종료와 마지막 줄 검사

## 상황과 근거

사용자는 실제 해결한 이슈를 여러 개 종료할 수 있도록 하고 `Changes:`는 비어 있지 않은 마지막 줄만 검사하도록 요청했다. 현재 PR 생성기는 마지막 두 줄에서 특정 이슈의 `Closes`를 요구하고 릴리즈 수집은 바로 앞의 중복 `Changes:`를 오류로 처리한다.

GitHub 공식 문서에는 여러 이슈를 종료할 때 각 이슈마다 종료 키워드를 사용하는 예시가 있다. 대상 플랫폼의 구문에 따라 실제 해결한 이슈만 적는다.

## 결정과 영향

PR 생성기의 마지막 `Changes:` 경로 검증은 유지하고 앞선 `Closes`의 위치나 개수는 검사하지 않는다. 릴리즈 수집은 마지막 비어 있지 않은 줄만 해석하며 기존 브랜치 기반 폴백과 잘못된 마지막 항목 오류는 유지한다.

기존에는 오류였던 인접한 중복 `Changes:`도 마지막 항목이 유효하면 마지막 경로를 사용한다. 공통 지침에는 이슈별 종료 구문을 안내하되 프로젝트별 종료 조건을 유지한다.

PR 생성기 테스트 69개와 릴리즈 노트 수집 테스트 7개가 통과했다. 실제 GitHub Actions와 PR 병합은 확인하지 않았다.
