# PR 본문 변경의 기존 동작과 확인 사항

## 상황과 근거

사용자는 기존 규칙을 버리지 않으면서 PR 본문 끝에 이슈 종료 구문과 `Changes:` 변경 로그 경로를 함께 기록하도록 요청했다. CI의 수집 방식 변경은 이후 작업으로 구분했다.

`.github/scripts/create-pr-from-issue.mjs`의 `buildPullRequest`는 현재 `Closes #번호`를 마지막 줄에 작성하며, 본문이 길면 내용이나 템플릿을 링크로 대체해 다시 생성한다. 기존 테스트는 변경 로그와 작업 문서가 없거나 비어 있는 경우에도 PR을 생성하는 동작을 확인한다. 이미 열린 PR은 메타데이터만 갱신하고 본문은 바꾸지 않는다.

## 해석과 결정

변경 로그가 없을 때 경로를 기록할지, 생략할지 또는 PR 생성을 중단할지에 따라 기존 동작과 경로의 유효성이 달라진다. 이미 열린 PR 본문을 수정하는지도 기존 동작과 사용자 작성 내용에 영향을 준다. 두 사항은 임의로 결정하지 않고 사용자에게 확인한다.

확정 전에는 PR 자동화나 CI를 변경하지 않는다. 분석 수행 내용은 [작업 기록](../tasks/1794057075718.md)에 남긴다.
