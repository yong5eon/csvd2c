# 에이전트 브랜치 PR 문서 연동 분석

## 상황과 근거

사용자는 `copilot/**`, `codex/**` 브랜치에서도 PR의 변경 파일 목록으로 이슈 `IR.md`를 찾아 PR 제목과 본문을 갱신하도록 요청했다. 실험 PR [#25](https://github.com/yong5eon/csvd2c/pull/25)는 `copilot/csv-iterator-support` 브랜치에 `issues/feature/2/IR.md`를 포함한다.

기존 워크플로는 네 이슈 브랜치 접두사에만 반응하며 생성기는 브랜치 이름에서 이슈 경로를 결정한다. PR #25에서는 `pull_request` CI 실행을 확인했으나 해당 워크플로의 에이전트 `push` 실행 여부는 확인하지 못했다.

## 결정과 영향

원본 이슈 #16이 종료됐고 이전 PR은 병합됐다. 사용자는 후속 작업을 이 이슈와 `task/16` 브랜치에서 이어가기로 했다. 원격 `master`의 자동화 파일은 현재 작업 브랜치와 동일하며 이슈 상태는 변경하지 않는다.

에이전트의 PR 본문 재갱신과 자동화 사이의 순서 보장은 이번 요청의 범위에 포함되지 않는다. 작업 계획과 상세 구현·검증은 후속 기록에 남긴다.

PR 파일 API는 최대 3,000개를 반환하므로 그 한도에 도달해 목록의 완전성을 입증할 수 없으면 임의의 문서를 선택하지 않는다. 첫 푸시에서 PR이 아직 없으면 새 PR을 만들지 않으며 이후 푸시에서 다시 처리한다. 문서가 여러 개면 선택 근거가 없어 오류로 중단한다.

기존 워크플로의 `push` 실행은 해당 브랜치에 있는 워크플로 정의를 따른다. 이미 생성된 에이전트 브랜치가 변경 사항을 포함하지 않으면 새 패턴이 적용되지 않으며 실제 이벤트와 원격 실행은 별도 확인이 필요하다.

변경 전 이미 PR head가 푸시 커밋보다 앞서 있다면 오래된 실행을 건너뛰도록 했다. 실행 도중 새 푸시나 에이전트의 PR 본문 수정이 발생하는 경우까지 원자적으로 방지하지는 않는다.

기존 워크플로는 푸시된 브랜치의 워크플로와 스크립트를 실행하면서 GitHub App 비밀키와 PR·이슈 쓰기 토큰을 사용한다. 대상 확장으로 에이전트 브랜치의 코드도 이 권한을 사용하는 신뢰 범위에 포함된다. 이번 변경은 권한 구조를 재설계하지 않았으며 브랜치의 워크플로와 스크립트에 대한 신뢰가 필요하다.
