# 구현 결과

아래는 초기 구현 당시의 결과다. 이후 사용자가 지침 통합과 원격 작업 방식을 변경했으며 현재 기준은 [요구사항](./REQUIREMENTS.md)과 [작업 결과](./TASKS.md)를 따른다.

루트 `AGENTS.md`를 추가해 GitHub Codex·Copilot 에이전트가 공통 작업 원칙과 csvd2c의 프로젝트 지침을 확인하도록 했다. 공통 지침 다섯 파일은 원본 커밋 `8706862712c800682f38af3c86e74f768345d811`의 내용 그대로 `instructions/common/`에 제공했다. 로컬 링크나 외부 저장소 접근에 의존하지 않게 한 이유는 GitHub 작업환경에서 저장소 밖 자료를 보장할 수 없기 때문이다. 커밋 메시지 작성 지침은 요청 범위에서 제외했다.

에이전트 지침에 CI가 읽는 `issues/task/16/CHANGELOG.md`의 존재·비어 있지 않음 확인을 추가했다. CI 경로는 PR 브랜치명에서 유도되므로 `task/16` 브랜치에서 해당 위치가 필수다.

## PR 자동 생성 후속 구현

`.github/scripts/create-pr-from-issue.mjs`의 `buildPullRequest`는 `IR.md` 본문의 마지막 비어 있지 않은 줄이 이슈별 변경 로그 경로인지 검증하고 본문을 그대로 사용한다. 이슈 종료 구문의 위치나 개수는 검사하지 않으며 항목은 본문 길이 제한 계산에 포함된다.

`createPullRequest`는 새 PR 생성과 기존 PR 갱신 전에 변경 로그와 `IR.md`의 누락·공백을 오류로 처리한다. 이전의 새 PR 생성 검증은 [작업 기록](./tasks/1794057212842.md)을 따른다.

이슈 브랜치에서 새 PR을 생성할 때는 GitHub API에 `draft: true`를 전달한다. 기존 열린 PR의 Draft 상태는 변경하지 않으며 자동으로 Draft를 해제하지 않는다.

열린 PR은 푸시된 `IR.md`로 제목·본문 전체를 다시 생성해 갱신하며, 수동 편집은 덮어쓴다. 기존 메타데이터·이슈 연결 동기화는 유지한다.

## CI 변경 로그 경로 수집

새 버전 릴리즈의 병합 PR에서 마지막 비어 있지 않은 줄의 이슈·비이슈 `Changes:` 경로를 우선 읽고, 항목이 없으면 기존 브랜치 기반 경로를 사용한다. 잘못된 마지막 항목은 오류로 처리하며 직접 push와 기존 릴리즈 노트 재사용은 유지한다. 비이슈 PR의 경로 작성 지침도 추가했다. 마지막이 아닌 항목은 인식하지 않으며 본문 끝의 예시를 실제 항목과 구분하지 못한다.

이후 릴리즈 노트 테스트의 CI 실행 단계만 제거했다. 테스트 파일은 관련 변경 시 직접 실행할 수 있도록 유지한다.

PR 제목은 작업자가 `IR.md` 첫 줄에 작성한 최상위 제목을 사용하고 본문은 나머지 내용을 사용한다. 제목이 본문에 중복되지 않으며 제목이나 본문이 유효하지 않거나 본문 길이 제한을 초과하면 오류로 중단한다. README나 원본 이슈 제목으로 대체하지 않는다.

공통 작업 지침의 변경 적용 요청 형식은 GitHub PR과 GitLab MR을 포괄하며 특정 템플릿 파일에 의존하지 않는다. csvd2c 자동화는 `IR.md`만 입력으로 읽으며 기존 `PR.md`는 사용하지 않는다.
