# 필드 제한 구현 방식과 검증 기준

## 상황과 목표

사용자가 [확정 명세](../REQUIREMENTS.md)와 [계획](../PLAN.md)에 따른 구현을 요청했다. 병합 대상은 `master`로 확정했으며 실제 병합 권한과는 구분한다.

## 근거와 결정

- `feature/22`의 변경 없는 작업 트리와 기존 기록을 확인했다.
- Windows 64비트 CPython 3.12.10에서 기존 CSV 테스트 36개가 통과했다. `131073`문자 필드를 기본 제한 `131072`로 읽으면 표준 `csv.Error`가 발생했다.
- editable import는 빌드 경로를 표시하지만 `os.path.samefile()`로 원본 `src/__init__.py`와 같은 파일임을 확인했다. 변경 후에도 실제 import 내용을 확인한다.
- 최대값은 모듈에 한 번 정의하고 패키지에서 재노출한다. 기존 생성자 검증·초기화 후에만 표준 설정을 호출하여 잘못된 입력의 전역 부작용을 방지한다.
- 기존 파서 경로를 유지하면 헤더·offset·데이터에 같은 제한이 적용된다. 인스턴스별 상태나 자동 복원을 추가하지 않는다.
- Python 공통 지침의 한국어 문구 규칙에는 프로젝트 `instructions/CODE.instructions.md`의 명시적 영어 예외를 적용한다. 사용자 문서·작업 기록은 한국어로 작성한다.

## 영향과 후속 검증

새 값을 지정한 생성자는 전역 설정을 변경하며, 기본 호출은 변경하지 않는다. 작은 합성 입력과 기존 테스트로 범위·오류·전역 영향·자원 정리를 검증하고, 사용 가능한 Python 3.10.11·3.12.10·3.14.5의 검증 범위를 구분하여 기록한다. 현재 구현은 미착수다.
