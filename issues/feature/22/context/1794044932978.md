# 전역 제한 문서화와 버전별 검증 판단

## 상황과 목표

[첫 구현 기록](../implements/1794044372545.md)의 API를 사용자 문서에 반영하고 [인수 기준](../REQUIREMENTS.md)에 따라 버전별 회귀를 확인했다.

## 근거·수정과 결정

- Python 3.12·3.14의 전체 테스트는 각각 190개가 통과했다.
- Python 3.10에서는 `patch('csvd2c.CSV.csv_field_size_limit')`가 모듈 대신 같은 이름의 클래스를 선택하여 새 테스트에서 `AttributeError`가 발생했다. 에이전트가 추가한 mock 대상의 버전 호환 문제로, 제품 설정 로직의 실패는 아니었다. `patch.object(modules[CSV.__module__], ...)`로 실제 모듈을 지정한 뒤 전체 190개가 통과했다. 다른 두 버전도 최종 CSV 테스트 47개를 재실행하여 통과했다.
- 한글 매뉴얼 예제의 첫 실행은 PowerShell 파이프의 한글 전달 문제로 섹션을 찾지 못했다. Pylance 집중 실행 도구로 실제 문서의 예제를 읽고 실행하여 두 언어의 기대 출력과 설정 복원을 확인했다.
- 기존 선택 interpreter의 editable 빌드가 이전 API를 가리키므로 Pylance 테스트 파일 진단에는 새 상수·매개변수의 오탐이 남았다. 제품 소스 진단과 설치 wheel의 실행 결과를 구분하고, 이를 전체 정적 검사 통과로 보고하지 않는다. 공유 개발 환경은 임의로 재설치하거나 interpreter 설정을 바꾸지 않았다.
- Python 3.14의 검증 환경 생성 시 다른 프로젝트의 기존 editable 연결에서 권한 오류가 출력됐다. 별도 환경 생성·wheel 설치·테스트는 성공했으며 다른 프로젝트는 수정하지 않았다.
- 설정 시점·전역 공유·자동 복원 없음은 문장과 실행 예제로 설명할 수 있어 추가 추상화나 도식은 만들지 않았다.

## 영향과 결과

한국어·영어 매뉴얼과 루트 README에 공개 API·오류·전역 및 메모리 제약을 반영했다. [검증 기록](../tasks/1794044932978.md)은 Windows 설치 wheel과 실제 문서 예제를 근거로 한다. Linux·Python 3.11·3.13 및 CI 실행은 미검증이다.
