# CSV 필드 크기 제한 설정 요구사항

## 목적과 범위

[원본 이슈](./README.md)의 큰 CSV 필드 읽기를 지원하면서 기존 생성자 사용 방식과 기본 동작을 유지한다. 이번 문서는 요구사항 명세이며, 아래 API와 동작은 아직 구현되지 않았다.

포함 범위는 생성자 설정, 공개 최대값 상수, 입력 검증, 전역 설정의 영향 안내 및 관련 테스트다. Python 최소 지원 버전 변경, 인스턴스별 독립 제한, 자동 최대값 선택·축소·재시도, `open()`의 추가 설정은 포함하지 않는다.

## 분석과 근거

- 현재 [CSV 생성자](../../../src/CSV.py)는 필드 크기 제한을 설정하지 않는다. 표준 `csv.reader`는 현재 전역 제한을 사용하며, 헤더·offset 건너뜀·데이터 읽기 모두 CSV 파싱을 거친다.
- [패키지 설정](../../../setup.py)의 최소 지원 버전은 Python 3.10이며, 분류에는 3.10~3.14가 명시되어 있다.
- 앞선 조사에서 Windows 64비트 CPython 3.12.10의 기본 제한은 `131072`였다. `csv.field_size_limit(sys.maxsize)`는 `OverflowError: Python int too large to convert to C long`을 발생시켰고, `2_147_483_647` 설정은 성공했다.
- [CPython 3.12 구현](https://github.com/python/cpython/blob/3.12/Modules/_csv.c)은 C `long`, [CPython 3.13 구현](https://github.com/python/cpython/blob/3.13/Modules/_csv.c)은 `Py_ssize_t`으로 제한값을 변환한다. 일반적인 CPython 3.10~3.14의 32·64비트 환경에 공통으로 제공할 상한은 `2_147_483_647`로 정한다. 모든 Python 구현·플랫폼에서 실행 검증한 값이라는 의미는 아니다.
- 표준 reader의 제한을 높이면 이미 생성된 reader도 더 큰 필드를 읽고, 낮추면 기존 reader도 새 제한으로 실패하는 것을 확인했다. 따라서 reader 생성 시 설정 후 즉시 복원하는 방식으로는 읽기 제한을 적용할 수 없다.
- 최대값 설정은 최대 크기만큼의 메모리를 즉시 할당하지 않는다. CPython 파싱 버퍼는 필드 길이에 따라 증가하므로, 큰 상한은 실제 처리 가능한 크기나 메모리 안전을 보장하지 않는다.

사용자는 기본값 `None`, 값이 있을 때만 설정, 최대값 상수 제공 및 최대값 초과 시 `ValueError`를 확정했다. 추가 확인에서 `0`을 허용하고 음수는 `ValueError`로 처리하며, 상수 이름은 `MAX_FIELD_SIZE`로 지정했다. 이를 클래스 속성이 아닌 패키지 공개 상수로 명세한다.

## 확정 요구사항

### R1. 선택적인 생성자 설정

- `CSV` 생성자에 키워드 전용 매개변수 `field_size_limit: Optional[int] = None`을 추가한다.
- 생략하거나 `None`을 전달하면 표준 `csv.field_size_limit()`의 현재 값을 변경하지 않는다. `None`은 무제한이나 표준 초기값으로의 복원을 뜻하지 않는다.
- 유효한 정수값이 지정되면 생성 시 표준 `csv.field_size_limit()`에 적용한다.
- 기존 매개변수와 기본 동작, 파일 읽기·검증·자원 관리 계약을 유지한다.

### R2. 공개 최대값 상수

- 패키지 공개 모듈 상수 `MAX_FIELD_SIZE`를 제공하며 값은 `2_147_483_647`이다.
- `from csvd2c import MAX_FIELD_SIZE`로 가져올 수 있게 공개 내보내기에 포함한다.
- 이 상수는 라이브러리가 허용하는 설정 상한이다. `sys.maxsize`나 런타임별 실제 최대 허용값을 자동으로 계산한 값이 아니다.
- 사용자가 `CSV(field_size_limit=MAX_FIELD_SIZE)`로 명시적으로 선택할 수 있다. 상수를 기본 설정으로 적용하지 않는다.

### R3. 허용 범위와 설정 오류

| 입력 | 동작 |
| --- | --- |
| `None` | 전역 설정을 변경하지 않음 |
| 정수 `0` 이상 `MAX_FIELD_SIZE` 이하 | 지정값 적용 |
| 음수 정수 | 생성자에서 `ValueError` |
| `MAX_FIELD_SIZE` 초과 정수 | 생성자에서 `ValueError` |
| `bool`, 문자열, 실수 등 정수가 아닌 값 | 생성자에서 `TypeError` |

- 범위·타입 오류를 표준 CSV 설정 호출 전에 검출하며 기존 전역 제한을 변경하지 않는다.
- 다른 생성자 인자의 검증 실패로 객체 생성이 거부되는 경우에도 필드 제한을 변경하지 않는다.
- 범위 내 값의 표준 설정 호출이 예상치 못하게 실패하면 해당 오류를 전파한다. 기본값 대체, 자동 축소, 조용한 무시는 하지 않는다.
- 오류 메시지는 잘못된 매개변수와 허용 조건을 식별할 수 있어야 하며, 프로젝트 코드 지침에 따라 영어로 작성한다.

### R4. 전역 영향과 읽기 오류

- 설정은 인스턴스 전용이 아니라 같은 인터프리터의 표준 `csv` 모듈 전역 설정이다. 기존 reader와 다른 `CSV` 인스턴스도 영향을 받는다.
- 뒤에 수행된 설정이 이후 읽기에 적용된다. 생성자 이후 외부 코드가 제한을 바꾸더라도 각 인스턴스가 자신의 설정을 다시 강제하지 않는다.
- `open()`·`close()`·컨텍스트 종료 시 전역 제한을 자동 복원하지 않는다. 임시 변경·복원이 필요하면 호출자가 관리해야 한다.
- 제한은 필드의 문자 수이며 파일 크기, 레코드 수 또는 바이트 수가 아니다.
- 길이가 설정값과 같은 필드는 허용하고, 설정값을 넘는 필드를 읽을 때는 표준 `csv.Error`를 그대로 전파한다. 이 읽기 오류를 생성자 입력 오류인 `ValueError`로 바꾸지 않는다.
- `0`은 빈 필드만 허용하며, 문자가 있는 필드는 `csv.Error`를 발생시킨다.
- 헤더, offset으로 건너뛰는 레코드 및 데이터 레코드에도 표준 파서 제한이 적용된다. 기존 읽기 경로를 우회하지 않는다.

### R5. 사용법과 제약 문서화

- 한국어·영어 상세 매뉴얼에 기본값 `None`, 명시적 설정과 `MAX_FIELD_SIZE` 사용법, 허용 범위 및 오류를 설명한다.
- 전역 영향, 자동 복원 없음, 다른 reader와의 공유 및 서로 다른 제한을 독립적으로 보장하지 않는다는 제약을 명시한다.
- 설정 상한과 실제 메모리에서 처리 가능한 크기는 다르며, 최대값도 메모리 부족을 방지하지 않는다고 설명한다.
- 공개 API 요약이 필요한 루트 README도 한국어·영어 범위를 맞춰 검토한다. 아직 구현되지 않은 기능을 현재 사용 가능한 기능처럼 문서화하지 않는다.

## 인수 기준

아래 항목은 구현 후 수행할 검증이며, 이번 명세 작성에서 통과한 테스트를 뜻하지 않는다. 테스트는 비민감 합성 데이터와 작은 필드로 수행하고, 변경한 전역 제한은 테스트 종료 시 복원한다.

| 요구사항 | 검증 기준 |
| --- | --- |
| R1 | 인자 생략 및 명시적 `None` 생성 시, 외부에서 지정한 전역 제한을 그대로 유지 |
| R1·R4 | 기본 상태에서 `131073`문자 필드 읽기 실패, 충분한 제한을 지정한 후 같은 필드 읽기 성공 |
| R2·R3 | 패키지에서 상수 가져오기 성공, 값 `2_147_483_647` 확인 및 해당 값 설정 성공 |
| R3 | `-1`, `MAX_FIELD_SIZE + 1`, 그보다 큰 정수에서 `ValueError`; 전역 제한 불변 |
| R3 | `True`, `False`, 문자열, 실수에서 `TypeError`; 전역 제한 불변 |
| R3 | 다른 생성자 인자의 검증 실패 시에도 전역 제한 불변 |
| R3 | 표준 설정 호출 실패가 그대로 전달되며 폴백이 없는지 확인 |
| R4 | 작은 제한 `N`에서 길이 `N` 필드 성공, `N + 1` 필드의 `csv.Error` 확인 |
| R4 | `0` 설정 성공, 빈 필드 성공, 한 문자 필드의 `csv.Error` 확인 |
| R4 | 다중 바이트 문자에서도 바이트 수가 아닌 문자 수로 경계 적용 |
| R4 | 기존 표준 reader 및 다른 `CSV` 인스턴스에 제한 변경이 반영되고, 종료 후 자동 복원되지 않음 |
| R4 | `row()`·`rows()`·헤더·offset 건너뜀 및 지원 읽기 모드에서 동일한 파서 제한 적용 |
| R1·R4 | 기존 생성자, 읽기·검증·자원 관리 회귀 테스트 유지 |
| R5 | 문서 예제와 구현 API 일치, 한국어·영어 설명 및 전역·메모리 제약 일치 |

최대값 검증은 설정 가능 여부를 확인하는 것이다. 약 21억 문자 데이터를 실제로 할당하거나 읽는 테스트는 요구하지 않는다.
