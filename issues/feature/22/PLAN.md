## 수행 순서

### 1. 구현 준비와 기준 동작 확인

선행 조건: 구현 요청. 병합 대상은 사용자 확정 완료.

1. 관련 공통·프로젝트 지침과 최신 이슈 기록을 확인한다. Python 변경 전에 공통 Python 개발 지침도 읽는다.
2. 대상 저장소의 브랜치가 `feature/22`인지, 기존 사용자 변경이 있는지 확인한다. 다른 브랜치의 변경을 섞거나 기존 기록을 덮어쓰지 않는다.
3. 사용할 인터프리터와 `csvd2c` import가 가리키는 소스를 확인한다. 오래된 설치본을 테스트하는 결과를 현재 변경의 검증으로 사용하지 않는다.
4. 기존 CSV 테스트를 최소 기준으로 실행하고, 표준 제한을 명시적으로 `131072`로 둔 상태에서 `131073`문자 필드의 실패를 확인한다. 검증 후 원래 전역 제한을 복원한다.

완료 기준: 구현 환경·실제 소스·기준 결과와 기존 실패 여부를 확인하고 기록.

### 2. 공개 상수와 생성자 설정 구현

선행 조건: 1단계 완료.

1. `src/CSV.py`의 모듈 수준에 `MAX_FIELD_SIZE: int = 2_147_483_647`을 한 번 정의하고 모듈 `__all__`에 포함한다.
2. `src/__init__.py`에서 기존 `CSV`와 함께 상수를 가져오고 패키지 `__all__`에 포함한다. `from csvd2c import MAX_FIELD_SIZE`를 공개 사용법으로 제공한다.
3. 기존 생성자의 마지막에 키워드 전용 `field_size_limit: Optional[int] = None`을 추가한다. 기존 인자 이름·기본값·키워드 전용 계약을 유지한다.
4. 표준 함수는 매개변수와 구분되는 이름으로 가져온다. 기존 `reader` import 형식을 따르며, 예를 들어 `field_size_limit as csv_field_size_limit`을 사용한다.
5. 지정값은 `bool`을 먼저 거부하고 정수 여부를 검사한다. 정수가 아니면 `TypeError`, `0` 미만 또는 `MAX_FIELD_SIZE` 초과면 `ValueError`를 발생시킨다. `None`은 검사와 설정 호출을 건너뛴다.
6. 기존 `check_header()`·`check_validators()`·`check_range()` 등 모든 생성자 검증과 초기화를 완료한 뒤, 반환 직전에 지정값을 표준 함수에 한 번 적용한다. 이후 실패할 수 있는 초기화 작업을 남겨 전역 설정만 바뀌는 상황을 만들지 않는다.
7. 표준 함수의 예상치 못한 예외를 그대로 전달한다. 자동 축소·재시도·기본값 대체는 추가하지 않는다.
8. 생성자 독스트링에 `None`, 허용 범위, 전역 영향 및 자동 복원 없음을 영어로 설명한다.

추가 인스턴스 상태에 설정값을 저장하거나 `open()`·`close()`·읽기 메서드에서 재설정하지 않는다. 실제 제한은 표준 파서의 현재 전역값이며, 기존 헤더·offset·데이터 읽기 경로를 유지한다.

완료 기준: 상수 가져오기 성공, 기본 생성 시 표준 설정 호출 없음, 지정값은 기존 검증 성공 후 한 번만 적용.

### 3. 입력과 읽기 동작 테스트 추가

선행 조건: 2단계 완료.

기존 `TestCase`·`TemporaryDirectory`·`subTest`·`unittest.mock.patch` 패턴을 사용한다. 전역 설정을 바꾸는 테스트는 변경 전에 원래 값을 저장하고 즉시 `addCleanup`으로 복원을 등록한다. 한 테스트 안의 하위 사례도 각 사례에 필요한 기준값을 명시하여 순서에 의존하지 않게 한다.

| 요구사항 | 구체적인 테스트 |
| --- | --- |
| R1 | `CSV()`와 `CSV(field_size_limit=None)`에서 외부 설정값 유지 및 표준 설정 함수 미호출 확인 |
| R1·R2 | 생성자 시그니처의 키워드 전용·`None` 기본값·타입 확인, 패키지 상수값과 `__all__` 내보내기 확인 |
| R2·R3 | `MAX_FIELD_SIZE` 설정 성공 확인. 최대 길이의 문자열은 만들지 않음 |
| R3 | `-1`, `MAX_FIELD_SIZE + 1`, `10 ** 100`은 `ValueError`; `True`, `False`, 문자열, 실수는 `TypeError`; 모든 실패에서 전역값 불변·설정 함수 미호출 확인 |
| R3 | 유효한 필드 제한과 잘못된 `header`·`row`·`column`·`offset`·`limit`을 조합하여 기존 검증 예외와 전역값 불변 확인 |
| R3 | 표준 설정 함수를 patch하여 예외를 발생시키고 동일 예외 전파·재시도 없음 확인 |
| R1·R4 | 제한 `131072`에서 `131073`문자 필드 실패 후, `131073`으로 설정하여 동일 입력 읽기 성공 |
| R4 | 작은 제한 `N = 3`에서 세 문자 성공·네 문자 `csv.Error`, 다중 바이트 문자도 동일 문자 수 경계 확인 |
| R4 | 제한 `0`에서 `""`로 표현한 빈 필드 성공·한 문자 필드 실패 확인. 빈 레코드만으로 빈 필드 테스트를 대신하지 않음 |
| R4 | `rb`·`r`·`rt`별 `row()`와 `rows()`에서 경계 적용 및 오류 전파 확인. header Validator와 offset 건너뜀에도 초과 필드를 배치하여 같은 파서 오류 확인 |
| R4 | 설정 변경 전에 생성한 표준 reader와 이미 열린 다른 `CSV`에서 이후 설정의 영향 확인. 높은 값·낮은 값의 순차 설정과 외부 변경으로 마지막 전역값 사용 확인 |
| R4 | `open()`·직접 `close()`·정상 및 예외 컨텍스트 종료 이후 제한 유지 확인. 읽기·열기·닫기에서 생성자 설정을 재적용하지 않음 |
| R1·R4 | 파싱 오류 후 스트림 정리와 `raw()` 상태 등 기존 계약 유지 확인 및 관련 회귀 테스트 실행 |

테스트는 작은 합성 파일로 수행한다. 약 21억 문자 필드, 메모리 소진, 병렬 reader의 독립 제한 보장 테스트는 범위에 넣지 않는다.

완료 기준: 명세의 입력·경계·전역 영향 인수 기준이 테스트에 대응하고, 테스트 종료 후 설정이 복원됨.

### 4. 사용자 문서 갱신

선행 조건: 2단계의 API 확정과 3단계 관련 테스트 통과.

1. 양쪽 상세 매뉴얼에 필드 크기 제한 절을 추가하고 목차에 연결한다.
2. `None` 유지, 작은 명시적 제한, `MAX_FIELD_SIZE` 가져오기와 선택 사용 예제를 제공한다. 예제에는 필요한 import와 입력·기대 결과를 포함한다.
3. 생성자 입력의 `TypeError`·`ValueError`와 실제 필드 초과의 `csv.Error`를 구분한다. `0`의 의미와 문자 수 기준을 설명한다.
4. 이미 생성된 reader도 영향받고 종료 후 자동 복원되지 않는다는 점을 설명한다. 필요할 때 호출자가 `try/finally`로 이전 값을 복원하는 사용법을 보여 주되, 동시 reader의 독립성을 보장한다고 안내하지 않는다.
5. 최대값은 메모리를 선할당하지 않지만 큰 필드의 메모리 부족을 막지 못한다고 명시한다.
6. 루트 README의 읽기 설정·주의사항에는 핵심만 반영하고 상세 설명은 매뉴얼로 연결한다. 한국어·영어 내용을 맞추고 예제를 현재 구현으로 검증한다.

전역 설정과 reader의 관계를 설명하는 Mermaid 다이어그램이 필요한지 검토한다. 단순한 설정 설명에 장식용 도식이나 독립 문서를 추가하지 않는다.

완료 기준: 실제 API와 두 언어의 예제·오류·제약이 일치하고 상대 링크가 유효함.

선행 조건: 3·4단계 완료.

1. 입력 검증 순서와 공개 내보내기, 읽기 경로 불변을 diff에서 확인한다.
2. 아래 최소 검증부터 실행하고 필요에 따라 범위를 확대한다. 기존 실패와 이번 변경에 따른 실패를 구분한다.
3. 실제 수행 단계의 근거·구현·검증은 이슈의 `context/`·`implements/`·`tasks/`에 같은 작업 단위의 타임스탬프로 기록한다. 종합 기록은 수행한 종류에 맞춰 작성하며, 계획 상태와 README 링크를 갱신한다.
4. 기능 구현과 매뉴얼 반영 후 이슈별 `CHANGELOG.md`에 고객 영향과 사용법·주의사항을 작성한다. 프로젝트 전체 릴리즈 기록은 변경하지 않는다.
5. 인수 기준의 미충족·미실행 항목, 환경별 확인 범위를 명시한다. 커밋·푸시·PR·병합·이슈 종료는 별도 요청 없이 수행하지 않는다.

완료 기준: R1~R5에 대응하는 실제 검증 결과와 남은 제한사항을 기록하고, 무관한 변경·임시 산출물 혼입이 없음.

## 검증 명령과 환경

명령은 저장소 루트에서, 현재 작업 소스를 반영한 `csvd2c`가 설치된 검증 환경의 `python`으로 실행한다. 실제 실행 전 interpreter와 import 경로를 확인한다.

1. 변경 전 기준 및 변경 후 CSV 동작 검증:

   ```shell
   python -m unittest discover -s tests -p "test_csv.py" -v
   ```

2. 읽기·헤더·범위·원문 상태까지 전역 영향 회귀 확인이 필요한 경우 전체 기존 테스트:

   ```shell
   python -m unittest discover -s tests -p "test_*.py" -v
   ```

3. 문서·diff 검토:

   ```shell
   git diff --check
   git status --short
   ```

기존 [CI](../../../.github/workflows/ci.yml)는 Linux의 Python 3.10~3.14에서 wheel을 깨끗한 환경에 설치하고 전체 `unittest`를 실행한다. 패키지 공개 상수도 설치된 배포본에서 확인하는 기존 절차를 활용한다. 실제 CI 실행은 실행 권한과 별도 요청 범위를 따른다.

Windows의 C `long` 상한 문제를 확인하려면 사용 가능한 64비트 CPython 3.10~3.12 중 하나에서도 상수 설정과 범위 초과 테스트를 실행한다. 해당 런타임이 없거나 CI를 실행하지 못하면 미검증으로 기록하며, Linux 결과를 Windows 검증으로 대체 보고하지 않는다. 새 테스트 도구나 의존성은 추가하지 않는다.

## 호환성과 실패 대응

- 기존 호출은 전역 제한을 변경하지 않는다. 기존 코드의 마이그레이션은 필요하지 않다.
- 새 인자를 사용하는 호출은 이후 모든 reader에 영향을 주는 전역 설정임을 전제로 한다. 자동 복원이나 별도 인스턴스 제한으로 우회하지 않는다.
- 검증 실패가 이번 변경으로 발생하면 관련 코드·테스트를 수정하고 해당 검증을 다시 수행한다. 무관한 기존 오류는 기록하고 임의로 수정하지 않는다.
- 구현 중 명세와 기술 제약이 충돌하면 구현을 중단하고 명세 변경 여부를 확인한다. 상수 축소·기본값 변경·예외 타입 변경으로 조용히 회피하지 않는다.
- 사용자 파일이나 외부 시스템을 변경하는 작업은 없다. 테스트 임시 파일과 전역 설정은 해당 검증이 책임지고 정리·복원한다.
