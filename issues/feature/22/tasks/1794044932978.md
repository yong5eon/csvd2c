# 설치 wheel 회귀와 매뉴얼 예제 검증

[판단과 정정 근거](../context/1794044932978.md)에 따라 이번 작업 소스를 반영한 로컬 wheel을 서로 분리된 검증 환경에 설치했다. 검증 환경과 출력은 저장소 밖의 작업용 임시 위치를 사용했다.

## 실제 검증

| Windows 64비트 CPython | 검증 | 결과 |
| --- | --- | --- |
| 3.10.11 | 최종 전체 `unittest` | 190개 통과 |
| 3.12.10 | 전체 `unittest`, mock 수정 후 최종 CSV 테스트 | 190개·47개 통과 |
| 3.14.5 | 전체 `unittest`, mock 수정 후 최종 CSV 테스트 | 190개·47개 통과 |

저장소 루트 기준 명령은 다음과 같다. `python`은 설치 wheel을 사용하는 해당 검증 환경의 interpreter를 뜻한다.

```shell
python -m unittest discover -s tests -p "test_*.py"
python -m unittest discover -s tests -p "test_csv.py"
```

- 공개 상수값·시그니처, `None`의 설정 미변경, 타입·범위 오류와 설정 함수 미호출, 표준 함수 실패의 동일 예외 전파를 확인했다.
- `131073`문자 읽기, 작은 경계·다중 바이트 문자·`0`, 헤더·offset·읽기 모드, 기존 reader의 전역 공유, 재적용·자동 복원 없음 및 파싱 오류 시 상태 정리를 확인했다.
- 양쪽 매뉴얼의 추가 Python 예제를 실제로 실행하여 세 줄의 기대 출력과 이전 전역 제한 복원을 비교했다.
- 설치 wheel의 `CSV.py`와 현재 `src/CSV.py`의 바이트 일치를 확인했다.
- 제품 `src/CSV.py`의 Pylance 진단은 없었다. 테스트 파일에서는 기존 editable API에 대한 `reportAttributeAccessIssue`·`reportCallIssue`와 기존 `VirtualCSV` 타입의 `reportArgumentType`이 관측됐다. 전자는 선택 환경의 이전 API 해석이며, 후자는 변경하지 않은 기존 코드다. 전체 정적 검사 통과로 보고하지 않는다.

## 제한과 후속 확인

- wheel은 기능 검증용 `0.0.0` 버전으로 생성됐으며 릴리즈·배포용 산출물이 아니다. 패키지 버전 정책은 변경하지 않았다.
- Linux·Python 3.11·3.13, 원격 CI는 실행하지 않았다. 최대값은 설정 가능 여부만 확인했으며 약 21억 문자 할당은 수행하지 않았다.
- 공유 개발 환경의 기존 editable 설치는 이번 변경 후 이전 파일을 가리킨다. 필요하면 사용자가 해당 개발 환경에서 editable 설치를 갱신해야 한다. 제품 코드와 설치 wheel의 검증 결과와 구분한다.
- 다른 프로젝트의 환경 연결 오류를 이번 작업에서 수정하지 않았다.
- 최종 검토에서 이슈 문서 링크·앵커·제목, 개인 절대 경로 없음, 변경한 Python 파일의 3.10 문법 및 `git diff --check`를 확인했다. 제품 `src/__init__.py`도 Pylance 진단이 없었다.
- 문서 검사 역시 첫 PowerShell 실행에서 한글 앵커 전달 때문에 실패했으며, Pylance 실행 도구로 같은 검사를 수행하여 통과했다. 이슈 README의 원문 구역은 변경 전 Git 내용과 일치한다.
- 이번 작업에서 만든 세 검증 환경과 wheel 출력만 정리했다. 원본 데이터·사용자 파일·공유 환경은 삭제하거나 재설치하지 않았다.
- 로컬 구현·문서 반영과 위 범위의 검증을 완료했다. 추가 승인 없이 커밋·푸시·병합은 수행하지 않는다.
