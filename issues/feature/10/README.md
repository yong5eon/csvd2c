## 목적

헤더 레코드를 검증할 수 있도록 헤더 검증기 주입을 지원해 주세요. 호출자가 헤더 일치 여부를 직접 비교하는 코드를 파일마다 반복하지 않고, 기존 Validator·Pattern·Error 구조로 헤더 검사를 표현하는 것이 목적입니다.

## 현재 동작과 문제

csvd2c 0.1.2의 `header()`는 다음 레코드를 검증 없이 헤더로 사용합니다.

- 이름 기반 컬럼 Validator를 사용하면 선언한 이름이 헤더에 정확히 한 번 있는지 확인합니다. 다만 이 검사는 첫 `row()` 호출 때 일반 `ValueError`로 발생합니다.
- 선언하지 않은 추가 컬럼, 빈 이름, 중복 이름, 순서 같은 헤더 조건은 검사할 방법이 없습니다.

그래서 호출자가 `sorted(header) != sorted(expected)`처럼 직접 비교하고 별도 오류를 만들어야 합니다.

## 요구사항

### 적용 범위

- csvd2c는 첫 레코드가 헤더인지 판단하지 않습니다. 헤더 여부는 호출자가 `header()`를 부르는지로 정해집니다.
- 헤더 검증은 `header()`를 호출할 때만 적용됩니다. 헤더 없는 파일에서 `header()`를 부르지 않으면 헤더 검증도 없습니다.
- 헤더 검증기를 주입하지 않으면 기존과 같이 검사 없이 헤더를 사용합니다. csvd2c가 빈 이름·중복 이름 등의 규칙을 기본으로 강제하지 않습니다. 위치 기반 Validator를 사용하는 입력에는 이런 헤더도 정상일 수 있기 때문입니다.

### 주입 위치

- 생성자와 `open()`에서 헤더 검증기를 받습니다.
- 생성자 값을 기본으로 사용하고, `open()`에 값을 넘기면 그 파일을 여는 동안에만 해당 값을 적용합니다. 이 규칙은 읽기 범위 offset·limit 이슈(#9)와 동일하게 적용합니다.
- `row()`, `rows()`의 기존 `header` 인자는 출력 헤더를 뜻합니다. 헤더 검증기 인자 이름이 이와 혼동되지 않게 정해 주세요.

### 검증 방식

- 새로운 검증 체계를 만들지 않고 기존 행 Validator·Pattern을 헤더 레코드에 적용합니다.
- 헤더 검증 실패는 `row.Error`로 전달합니다. 헤더의 물리 행 번호와 검증에 전달된 헤더 값을 포함합니다.
- 실패한 헤더는 현재 헤더로 설정하지 않습니다. 이후 이름 기반 컬럼 Validator 매핑에 사용하지 않습니다.
- 헤더 Validator의 반환값을 헤더 이름으로 사용합니다. Pattern이 헤더 이름을 바꾸면 이름 기반 컬럼 매핑에도 바뀐 이름이 적용되므로 이 동작을 문서화합니다.
- 이름 기반 컬럼 Validator의 선언 이름이 헤더에 정확히 한 번 있어야 한다는 매핑 조건은 유지합니다. 이것은 헤더 내용에 대한 판단이 아니라 매핑이 성립하기 위한 조건입니다.

### 제공할 헤더 Pattern

자주 쓰는 헤더 검사를 행 Pattern으로 제공해 주세요. 호출자는 필요한 Pattern만 조합합니다.

- 빈 이름 거부
- 중복 이름 거부
- 지정한 컬럼이 모두 존재하는지 검사
- 지정한 컬럼과 정확히 같은 집합인지 검사(순서 무관, 추가 컬럼 거부)
- 지정한 순서와 정확히 같은지 검사

이름은 대소문자·공백을 바꾸지 않고 정확히 비교합니다. BOM 처리나 뒤쪽 빈 헤더 제거 같은 입력별 보정은 기본 동작으로 넣지 않으며, 필요한 호출자가 Pattern으로 선택합니다. 데이터 레코드의 컬럼 수 검사는 기존 행 Validator(`Length` 등)가 담당합니다.

## 검증 기준

- 헤더 검증기 미주입 시 기존 동작 유지
- 생성자 기본값과 `open()` 지정값의 적용·재오픈 시 적용
- 제공 Pattern별 성공·실패
- 실패 시 `row.Error`의 행 번호·헤더 값과, 실패한 헤더가 매핑에 사용되지 않음
- 헤더 Validator가 이름을 바꾼 경우 이름 기반 컬럼 매핑 결과
- 이름 기반 컬럼 Validator의 기존 매핑 조건 유지
- 헤더 없는 파일에서 `header()`를 부르지 않는 사용 방식에 영향 없음

검증 데이터는 비민감 합성 CSV를 사용합니다.
