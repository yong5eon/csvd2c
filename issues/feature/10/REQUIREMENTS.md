# 헤더 검증기 주입 요구사항

## 목적과 근거

[이슈 원문과 작업 메타데이터](./README.md)를 기준으로, 호출자가 헤더 비교 코드를 반복하지 않고 검증기 주입으로 헤더를 검사할 수 있게 한다.

후속 사용자 요구에 따라 원문과 다른 다음 결정을 적용한다. 원문과 충돌하는 부분은 사용자 요구를 따른다.

| 항목 | 이슈 원문 | 사용자 요구(우선) |
| --- | --- | --- |
| 검증 체계 | 기존 행 Validator·Pattern을 헤더에 적용, 실패는 `row.Error` | `csvd2c.header` 패키지에 Validator·Pattern·Error를 별도로 둔다 |
| 검증 호출 | 헤더 값과 물리 행 번호 전달 | `List[str] -> List[str]`, 라인 번호·열 정보를 받지 않는다 |
| 주입 인자 이름 | 출력 `header`와 혼동되지 않는 이름 | 생성자·`open()`에서 `header`로 받는다 |
| 검증 시점 | `header()` 호출 시 | 헤더 검증기가 있으면 `open()` 시점에 헤더를 읽고 검증한다 |
| `header()` | 다음 레코드를 읽어 헤더로 사용 | 검증된 헤더를 저장해 두었다가 반환하고, 검증이 없었으면 `None` 반환 |
| 미주입 시 | 기존 동작 유지 | `header()`는 `None` 반환 |
| 열 검증기 인자 | 언급 없음 | `cols`를 `column`으로 변경 |
| 출력 dict 변환 | 언급 없음 | `row()`·`rows()`의 출력용 `header` 인자 제거 |

## 현재 구조 분석

- [CSV](../../../src/CSV.py)의 `header()`는 호출할 때마다 다음 레코드를 검증 없이 읽어 `header_data`에 저장하고 복사본을 반환한다. 파일 끝에서는 `StopIteration`을 발생시킨다.
- `open(path, mode)`는 파일 단위 설정을 받지 않고 레코드를 소비하지 않는다. `open()`과 `close()`에서 `header_data`를 초기화한다.
- 이름 기반 열 매핑은 `header_data`에서 선언 이름이 정확히 한 번인지를 첫 `row()`·`rows()` 때 확인하고, 아니면 `ValueError`를 발생시킨다. 헤더가 없으면 `RuntimeError`이다.
- 열 검증기는 생성자와 `row()`·`rows()`의 `cols` 인자로 받는다. `src`에서 29곳, 테스트·샘플·매뉴얼·루트 README 14개 파일이 `cols`를 사용한다.
- `row()`·`rows()`에는 검증 후 값을 지정한 키에 연결해 dict로 반환하는 출력용 `header` 인자가 있다. 상세 매뉴얼과 샘플 5개(`read_dictionary.py`, `custom_patterns.py`, `reject_records.py`, `row_padding.py`, `column_recover_encoding.py`)에서 사용한다.
- 헤더 이름 검사용 기존 Pattern은 반복 헤더를 거부하는 행 Pattern `RejectHeader(*names)`뿐이다.
- `open()` 단위 덮어쓰기 규칙을 함께 쓰는 [#9](https://github.com/yong5eon/csvd2c/issues/9)는 미구현이다.

## 포함 범위

### R1. `csvd2c.header` 패키지

- `csvd2c.header`에 `Validator`, `Pattern`, `Error`를 추가한다.
- `Pattern`과 `Validator`의 호출 계약은 `__call__(self, value: List[str]) -> List[str]`이다. 라인 번호·열 식별자는 받지 않는다.
- `Validator`는 Pattern을 순서대로 적용하고 앞 Pattern의 반환값을 다음 Pattern에 전달한다. 최종 반환값을 헤더 이름으로 사용한다.
- `Error`는 공통 `csvd2c.Error`를 상속한 예외이며 `__init__(self, message: str, value: Optional[List[str]])`로 생성한다. `value`는 실패한 Pattern에 들어온 헤더 값이며, 읽을 헤더 레코드가 없으면 `None`이다. 라인 번호·열 식별자는 갖지 않는다.
- 이름은 대소문자·공백을 바꾸지 않고 정확히 비교한다. BOM 처리나 뒤쪽 빈 헤더 제거 같은 보정은 기본 동작에 넣지 않는다.

### R2. 주입 위치

- 생성자와 `open()`에서 헤더 검증기를 `header` 인자로 받는다.
- 생성자 값을 기본으로 사용한다. `open()`에 값을 넘기면 그 파일을 여는 동안에만 적용하고, 닫은 뒤 다시 열면 생성자 값을 사용한다.
- `open()`에 `None`을 넘기거나 생략하면 생성자 값을 사용한다.

### R3. open 시점 검증

- 적용할 헤더 검증기가 있으면 `open()`은 첫 레코드를 헤더로 읽고 검증한 뒤 컨텍스트를 연다.
- 검증에 성공하면 반환값을 현재 헤더로 저장한다.
- 검증에 실패하면 예외를 `open()` 호출자에게 전파하고 파일을 닫는다. 실패한 헤더는 저장하지 않는다.
- 헤더 검증기가 있는데 읽을 레코드가 없으면 `value`가 `None`인 헤더 `Error`를 발생시키고 파일을 닫는다.
- 적용할 헤더 검증기가 없으면 기존처럼 `open()`은 레코드를 읽지 않는다.

### R4. header()

- `header()`는 레코드를 읽지 않고 저장된 검증 헤더의 복사본을 반환한다.
- 헤더 검증이 이루어지지 않았으면 `None`을 반환한다. 반환 타입은 `Optional[List[str]]`이다.

### R5. 이름 기반 열 매핑

- 이름 기반 열 검증기는 저장된 검증 헤더를 기준으로 매핑한다. 헤더 검증기가 이름을 바꾸었다면 바뀐 이름으로 매핑한다.
- 선언 이름이 헤더에 정확히 한 번 있어야 하는 기존 매핑 조건과 오류 타입은 유지한다.
- 헤더가 없을 때 이름 기반 열 검증기를 사용하면 기존처럼 오류로 처리한다. 안내 문구는 헤더 검증기 주입을 기준으로 바꾼다.

### R6. 열 검증기 인자 이름 변경

- 생성자와 `row()`·`rows()`의 열 검증기 인자 `cols`를 `column`으로 변경한다.
- 이전 이름 `cols`의 호환 별칭은 두지 않는다. 기존 호출 코드의 변경이 필요하며 이를 문서에 명시한다.

### R7. 제공 헤더 Pattern

이슈 원문이 요청한 헤더 검사를 `csvd2c.header` Pattern으로 제공한다. 호출자는 필요한 Pattern만 조합한다.

| 검사 | 실패 조건 |
| --- | --- |
| 빈 이름 거부 | 정확히 빈 문자열인 이름이 있음 |
| 중복 이름 거부 | 같은 이름이 두 번 이상 있음 |
| 컬럼 수 | 헤더 이름 개수가 지정한 수와 다름 |
| 지정 이름 포함 | 지정한 이름 중 없는 것이 있음 |
| 정확한 구성 | 순서를 무시하고 비교했을 때 지정한 이름 목록과 다름 |
| 정확한 순서 | 지정한 이름 목록과 순서까지 정확히 같지 않음 |

- 헤더 이름은 중복될 수 있으며 각각 별개의 헤더로 본다. 정확한 구성 검사는 집합이 아니라 이름 목록을 정렬해 비교한다. 예를 들어 `a,a,b`는 `a,b`와 다르고 `b,a,a`와 같다.
- 빈 이름 거부는 각 이름이 빈 문자열인지 검사한다. 필드가 없는 빈 헤더 라인(`[]`)은 빈 이름이 없으므로 통과하며, 컬럼 수나 이름 목록 검사로 거부한다. 컬럼 수 검사는 사용자 요청으로 원문 목록에 추가했다.
- 데이터 레코드의 컬럼 수 검사는 기존 행 Validator(`Length` 등)가 담당한다.

### R8. row()·rows()의 출력용 header 인자 제거

- `row()`·`rows()`에서 검증 후 값을 지정한 키에 연결해 dict로 반환하는 `header` 인자를 제거한다. CSV는 레코드를 읽고 검증하는 역할이며, 헤더 이름을 바꾸려면 헤더 검증기에서 처리한다.
- `row()`는 `List[str]`, `rows()`는 `List[str]`를 생성하는 Generator만 반환한다. 반환 타입 분기를 위한 `@overload` 선언과 출력 헤더 처리 코드를 함께 제거한다.
- 헤더 검증기 없이 헤더가 있는 파일을 읽으면 첫 `row()`·`rows()` 결과는 헤더 레코드이다. 호출자가 그렇게 사용한 것으로 보고 별도로 처리하지 않는다.

### R9. 문서

- 한국어·영어 매뉴얼과 루트 README에 헤더 검증기, `open()` 시점 검증, `header()` 반환 변경, `cols` → `column` 변경, 출력용 `header` 인자 제거와 마이그레이션 방법을 반영한다.

## 호환성 영향

- `header()`가 레코드를 읽지 않게 되므로, 헤더를 읽으려면 헤더 검증기를 주입해야 한다. 기존 `csv.header()` 호출로 헤더를 소비하던 코드는 동작이 바뀐다. 검사 없이 헤더만 읽으려면 Pattern 없는 `csvd2c.header.Validator()`를 주입한다.
- 헤더 검증기 없이 `header()`를 반복 호출해 다음 레코드를 읽던 동작은 없어진다.
- `cols` 인자를 사용하던 코드는 `column`으로 바꿔야 한다.
- `row(header=...)`·`rows(header=...)`로 dict를 받던 코드는 반환된 list를 호출자가 직접 변환해야 한다. 예: `dict(zip(csv.header(), record))`.

## 제외 범위

- 읽기 범위 offset·limit([#9](https://github.com/yong5eon/csvd2c/issues/9))
- 첫 레코드가 헤더인지 자동 판단
- BOM·뒤쪽 빈 헤더 등 입력별 보정 Pattern
- `cols` 호환 별칭

## 인수 기준

다음 항목은 구현 후 검증할 기준이며 현재 통과를 의미하지 않는다. 검증에는 비민감 합성 CSV를 사용한다.

| 기준 | 검증할 결과 |
| --- | --- |
| A1 · R1·R3 | 헤더 검증기가 있으면 `open()`이 첫 레코드를 헤더로 검증하고, 성공 시 반환값이 `header()` 결과가 됨 |
| A2 · R1·R3 | 검증 실패 시 `value`가 실패한 Pattern의 입력 헤더인, 빈 파일 시 `value`가 `None`인 헤더 `Error`를 `open()`이 전파하고 파일이 닫힘 |
| A3 · R2 | 생성자 기본값, `open()` 지정값의 해당 파일 한정 적용, 재오픈 시 생성자 값 복원 |
| A4 · R3·R4 | 헤더 검증기가 없으면 `open()`이 레코드를 읽지 않고 `header()`가 `None`, 첫 `row()`가 첫 레코드를 읽음 |
| A5 · R4 | `header()`가 레코드를 소비하지 않고 반복 호출해도 같은 헤더의 복사본을 반환 |
| A6 · R5 | 헤더 검증기가 이름을 바꾼 경우 바뀐 이름으로 이름 기반 매핑, 기존 매핑 조건 유지 |
| A7 · R6 | 생성자와 `row()`·`rows()`에서 `column` 인자로 열 검증기 지정, `cols` 미지원 |
| A8 · R7 | 제공 Pattern별 성공·실패, 정확한 비교, 중복 이름을 별개로 보는 구성 비교, 빈 헤더 라인의 컬럼 수 검사 |
| A9 · R8 | `row()`·`rows()`에 `header` 인자가 없고 항상 list를 반환하며, 헤더 검증기 없이 읽으면 첫 결과가 헤더 레코드 |
| A10 · R9 | 매뉴얼·README 예시가 변경된 API로 실행됨 |
