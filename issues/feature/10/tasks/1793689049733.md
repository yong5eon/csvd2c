# 이슈 원문과 현재 헤더 처리 구조 분석

## 현재 코드

- `src/CSV.py`의 `header()`는 `next(reader)` 결과를 그대로 `header_data`에 저장하고 복사본을 반환한다. 검증·라인 번호 확보가 없다.
- `open(path, mode)`는 파일 단위 설정을 받지 않는다. 생성자 설정만 사용하며, `open()`·`close()`에서 `header_data`를 `None`으로 초기화한다.
- 이름 기반 열 매핑 조건(선언 이름이 헤더에 정확히 한 번)은 `column_indices()`가 첫 `row()`·`rows()` 호출 때 `ValueError`로 검사한다. 이슈는 이 조건 유지만 요구한다.
- 기존 행 Pattern 중 헤더 이름 검사는 반복 헤더를 거부하는 `RejectHeader(*names)`뿐이다. `RejectEmpty`는 모든 필드가 빈 레코드만 거부한다. 요청된 5가지 헤더 검사는 없다.
- 행 Validator·Pattern은 `(value, row)`를 받고 실패 시 `row.Error(message, row, value)`를 발생시키므로, 헤더에도 같은 구조를 그대로 적용할 수 있다.
- `open()` 단위 덮어쓰기 규칙을 공유하는 [#9](https://github.com/yong5eon/csvd2c/issues/9)는 미구현(OPEN) 상태다.

## 원문 요구와 필요한 최소 동작

- 생성자·`open()`에 헤더용 행 Validator를 받는다. `open()` 값은 그 파일을 여는 동안만 적용한다.
- `header()`에서만 검증한다. 미주입 시 기존과 같다.
- 실패 시 `row.Error`를 발생시키고 현재 헤더로 설정하지 않는다. 성공 시 Validator 반환값을 헤더 이름으로 쓴다.
- 빈 이름·중복 이름 거부, 지정 이름 포함, 정확한 집합, 정확한 순서 검사 행 Pattern 5개를 제공한다. 이름은 정확히 비교한다.

## 확인이 필요한 사항

- 헤더 검증기 인자 이름. `row()`·`rows()`의 출력 `header`와 구분되어야 한다.
- 제공 Pattern 5개의 이름과, 정확한 집합 검사에서 중복 이름을 허용할지.
- 실패 시 이전에 성공한 헤더가 있으면 유지할지 해제할지.
- `open()`에 `None`을 넘기면 생성자 값 사용으로 볼지. 이 경우 파일 단위 해제는 빈 `Validator()`로 가능하다.
- #9와의 구현 순서. `open()` 덮어쓰기 구조를 공유하지만 이번 범위에서 offset·limit은 구현하지 않는다.
- BOM·뒤쪽 빈 헤더 보정 Pattern은 제공 목록에 없으므로 이번 범위에서 제외할지.
- 병합 대상 브랜치.
