- GitHub 이슈 #13을 다시 조회했다. 원문은 보존된 내용과 같고 댓글은 없으며 `feature` 레이블이 적용되어 있었다.
- 작업 브랜치 `feature/13`과 깨끗한 작업 트리를 확인했다. 기존 커밋 `56beed6`은 이슈 README만 추가한 상태이며 제품 구현은 없었다.
- `instructions/`의 코드·루트 README·매뉴얼 지침과 공통 Markdown 지침을 확인했다. 독립 문서와 사용자 설명은 한국어, 향후 Python 코드 안 설명은 프로젝트의 영어 정책을 적용한다.
- `src/CSV.py`, 행 Validator, 헤더·행·컬럼 오류, 읽기·범위·헤더·오류 문맥 테스트, 상세 매뉴얼과 거부 기록 샘플을 대조했다.
- 현재 헤더는 `open()`이 소비하고 `header()`는 조회만 한다는 차이를 명세에 반영했다.
- 요구사항과 최소 해결 방향, 제외 범위, 인수 기준을 [요구사항 명세](../REQUIREMENTS.md)에 기록했다.

## 실행 확인

Pylance 실행 도구에서 선택된 작업공간 가상환경으로 저장소 `src`를 직접 패키지 로딩하고 임시 합성 CSV를 읽었다. 별도 설치나 제품 코드 변경은 하지 않았다.

- `CSV.raw`는 존재하지 않았다.
- 공백 필드에 `Strip`, `Required`를 적용한 오류의 `value`는 원래 공백 문자열이 아닌 `''`였으며 물리 라인은 1이었다.
- 검증 오류가 전파된 동일 `rows()` generator를 다시 순회하면 `[]`였다.
- 같은 열린 CSV에서 이후 `row()`는 다음 레코드 `['ok', 'next']`를 반환했다.
- 컨텍스트 종료 후 reader는 `None`이었다.

저장소 루트에서 작업공간 가상환경의 `python`으로 다음 기존 테스트를 실행했다. `PYTHONPATH`에 저장소의 `tests`를 지정했고, import된 `csvd2c`가 이 저장소의 `src/__init__.py`인지 확인했다.

```shell
python -m unittest test_csv test_range test_header test_error_context
```

결과: 93개 테스트 통과. 새 API 구현 전 관련 기존 계약의 기준 확인이며, 신규 인수 기준 통과를 뜻하지 않는다.
