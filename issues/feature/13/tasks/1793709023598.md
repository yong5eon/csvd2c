# 설치 wheel의 지원 경계 버전과 최종 인수 검증

## 빌드와 전체 테스트

작업공간 환경에는 `build` 실행 도구가 없어 최초 빌드 명령이 실패했다. 임시 Python 3.14 검증 환경에 기존 CI가 사용하는 build·setuptools·setuptools-scm·wheel 도구를 설치하고 다시 빌드했다. 공유 가상환경이나 프로젝트 의존성은 변경하지 않았다.

저장소 루트에서 실행한 빌드 명령:

```shell
python -m build --no-isolation --wheel --outdir <임시-wheel-출력>
```

이후 Python 3.10.11과 3.14.5의 별도 가상환경에 해당 wheel을 `pip install --no-index --no-deps`로 설치했다. 각 환경에서 저장소 밖을 실행 위치로 하여 기존 CI와 같은 테스트 탐색을 실행했다. 아래 테스트 경로는 저장소 루트 기준 표기이며 실행 시 해당 저장소 테스트 위치를 지정했다.

```shell
python -I -m unittest discover -s tests -p 'test_*.py'
python -m pip check
```

| 환경 | 결과 |
| --- | --- |
| Python 3.10.11 설치 wheel | 전체 179개 통과, 의존성 충돌 없음 |
| Python 3.14.5 설치 wheel | 전체 179개 통과, 의존성 충돌 없음 |

두 실행 모두 신규 원문 테스트 15개와 샘플 24개의 독립 프로세스 실행을 포함한다. Python 3.11~3.13 및 원격 GitHub Actions는 이번 로컬 검증에서 실행하지 않았으며 CI 매트릭스에는 유지했다.

설치가 끝나기 전 시작된 첫 메타데이터 조회는 패키지 미발견으로 실패했다. 설치 완료 뒤 다시 조회해 `Requires-Python: >=3.10`, Python 3.10~3.14 분류자, 3.9 분류자 부재를 확인했다.

## 타입·문서와 인수 기준

- 현재 소스에 직접 연결한 임시 분석 경로에서 Pyright 1.1.414, Python 3.10·basic 기준으로 `src/CSV.py`, `tests/test_raw.py`, `tests/test_samples.py`, `samples/reject_records.py` 총 4개 파일을 검사했다. 오류·경고·정보 모두 0건이다.
- 한국어·영어 매뉴얼의 신규 덤프 예시는 코드가 동일하고 Python 3.10 설치 wheel로 각각 실행·assert가 통과했다.
- A1~A11은 신규 원문 테스트로, A12는 기존 회귀 테스트와 실행 샘플·양언어 예시로 확인했다. A13은 버전 선언·wheel 메타데이터·지원 경계 버전 전체 테스트로 확인했다.
- 활성 메타데이터·CI·샘플 안내에 기존 Python 3.9 지원 선언이 남지 않았음을 검색으로 확인했다. 과거 검증 기록과 변경 사유의 3.9 표기는 보존했다.
- 사용자 매뉴얼에 반영한 동작과 Python 업그레이드 안내를 고객용 변경 로그에 정리했다.

Pylance 편집기에서 나타난 패키지 참조 관련 진단 자체를 수정했다고 주장하지 않는다. 별도 타입 검사와 설치 wheel 검증으로 현재 소스를 검증했으며, 조사 내용은 [앞선 검증 기록](./1793708570688.md)을 따른다.

## 완료 점검

- 관련 문서 22개의 상대 링크와 이슈 기록의 개인 절대 경로 검사를 통과했다. `git diff --check`도 통과했다.
- 변경은 원문 조회와 승인된 최소 Python 버전 변경, 관련 테스트·문서·이슈 기록에 한정되어 있다.
- 이번에 만든 임시 검증 환경 2개, wheel, 분석 설정과 패키지 연결만 정리했다. 프로젝트 소스가 유지되며 현재 브랜치가 `feature/13`임을 다시 확인했다.
- 커밋·푸시·이슈 변경·배포는 수행하지 않았다.
