# 원문 레코드 조회 구현 결과

## 제공 동작

[요구사항](./REQUIREMENTS.md)의 R1~R6를 반영했다.

- [CSV](../../../src/CSV.py)의 `raw()`는 `Optional[List[str]]`를 반환한다. 원문은 파싱·디코딩 후 행·컬럼 검증 전 필드 목록이며 매번 복사본으로 조회한다.
- `read_record()` 시작에서 이전 상태를 비우고 범위 안 레코드 파싱 직후 복사한다. 검증 후 복사하면 앞선 Pattern이 바꾼 값만 남는 문제를 검증 전에 보존하는 방식으로 해결했다.
- `row()`와 `iterate()`가 같은 읽기 함수를 사용하므로 성공·행 오류·컬럼 오류 모두 동일하게 원문을 보존한다. 기존 limit 계산과 오류 객체는 변경하지 않았다.
- 레코드를 얻지 못한 읽기 시도와 close·재open에서는 `None`이다. 헤더 자동 읽기와 offset 레코드는 제외하며 헤더 조회나 generator 생성은 원문을 바꾸지 않는다.
- 검증 오류 후 동일 generator는 종료된다는 Python 계약을 유지한다. 열린 컨텍스트 안에서 오류를 잡고 `raw()`를 저장한 뒤 다음 `row()`로 계속 처리할 수 있다.

문자열 필드 목록만 복사하므로 깊은 복사나 과거 레코드 이력 저장은 추가하지 않았다. 원문 전체를 오류 객체에 넣거나 파일을 다시 읽는 우회도 사용하지 않았다.

## 문서와 호환성

한국어·영어 상세 매뉴얼에 상태 전이·컨텍스트 제약·CSV 덤프 예시를 추가했고 루트 README·샘플 안내를 동기화했다. 기존 거부 기록 샘플은 오류 `value`와 별도로 `raw`를 JSONL에 기록한다.

Python 3.9의 표준 writer가 escape 문자를 손실하는 제약을 확인한 뒤 사용자 승인으로 최소 버전을 3.10으로 올렸다. `setup.py`, CI 매트릭스, 샘플 구문 검사와 설치 문서를 맞췄다. 기존 Python 3.9 사용자는 업그레이드해야 하며 CSV 설정·데이터 마이그레이션은 없다.

## 검증과 제한

- Python 3.10.11·3.14.5에 설치한 wheel에서 각각 전체 테스트 179개 통과
- 각 전체 실행에 원문 테스트 15개와 샘플 24개 실행 포함
- 변경 Python 동작·테스트 4개 파일의 Pyright 검사 오류·경고 없음
- 양언어 CSV 덤프 예시 실행 및 wheel 최소 버전·분류자 검증 통과

상세 명령과 Pylance 참조 문제에 대한 대체 검증, 미실행 환경은 [최종 검증 기록](./tasks/1793709023598.md)에 있다. 원격 CI·Python 3.11~3.13은 이번에 실행하지 않았다. 로컬 구현 완료이며 커밋·푸시·병합·배포 완료를 뜻하지 않는다.
