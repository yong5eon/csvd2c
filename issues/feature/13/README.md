## 목적

마지막으로 읽은 레코드의 원문, 즉 행·컬럼 검증기를 적용하기 전의 필드 목록을 돌려주는 `raw()` 메서드를 추가해 주세요. 검증에 실패한 레코드를 원문 그대로 덤프해 두었다가, 고친 뒤 같은 검증을 거쳐 다시 넣을 수 있게 하려는 것입니다.

## 현재 동작과 문제

csvd2c 0.1.4에서 검증에 실패한 레코드의 원문 전체를 호출자가 얻을 방법이 없습니다.

- `ColumnError`에는 실패한 컬럼 값(`value`), 컬럼(`column`), 물리 행 번호(`row`)만 있습니다. 컬럼 오류는 값 하나의 실패라는 계약이므로 행 전체를 여기에 넣는 것은 맞지 않습니다.
- `validate()`는 `record[index] = validator(...)`로 레코드를 제자리에서 바꿉니다. 실패 시점의 레코드는 앞쪽 컬럼이 이미 클린징된 상태라 원문이 아닙니다.
- `row()`는 실패해도 레코드를 소비합니다. 예외 처리 안에서 다시 읽으면 다음 레코드를 읽게 됩니다.
- `RowError.value`도 실패한 행 Pattern에 들어간 값입니다. 앞선 행 Pattern이 바꾼 값일 수 있어 원문이 아닙니다.

결국 호출자는 원본을 따로 다시 읽거나, 행만 읽고 컬럼 검증을 직접 반복하는 우회 코드를 써야 합니다.

## 요구사항

### raw()

- `raw()`는 마지막으로 읽기를 시도한 레코드의 원문 필드 목록(`List[str]`)을 돌려줍니다. 원문은 CSV 파싱과 디코딩은 끝났지만 행·컬럼 검증기는 적용하기 전의 값입니다.
- 매번 복사본을 돌려줍니다. 호출자가 반환값을 바꿔도 내부 상태와 이후 호출 결과는 바뀌지 않습니다.
- `RowError`, `ColumnError`, `HeaderError`의 계약과 Pattern 시그니처는 바꾸지 않습니다.

### 갱신 규칙

- `row()`와 `rows()`가 레코드를 하나 읽을 때마다 갱신합니다. 검증 성공, `RowError`, `ColumnError` 모두 해당합니다.
- `offset`으로 건너뛴 레코드와 `header()`로 읽은 레코드에는 반영하지 않습니다.
- 읽기 시도가 레코드를 만들지 못하면 `None`이 됩니다. 파일 끝, limit 도달에 따른 `StopIteration`, CSV 파싱·디코딩 오류가 해당합니다. 이전 레코드를 잘못 돌려주지 않기 위해서입니다.
- 아직 읽은 레코드가 없을 때와 `close()`, 재`open()` 후에는 `None`입니다.

### row()와 rows()에서의 사용

- `row()` 반복 호출에서는 예외를 잡은 곳에서 `raw()`로 실패 레코드의 원문을 얻고 다음 레코드로 계속 진행할 수 있어야 합니다.

```python
while True:
	try:
		record = csv_file.row()
	except StopIteration:
		break
	except (RowError, ColumnError):
		dump.writerow(csv_file.raw())
		continue
```

- `rows()`는 generator라서 검증 예외가 나면 Python generator 동작에 따라 순회가 끝납니다. 이때도 `raw()`는 실패한 레코드의 원문을 돌려줘야 합니다. 문서에는 실패 후에도 계속 처리하려면 `row()`를 반복 호출해야 한다는 점을 적습니다.

### 원문의 범위

- `raw()`는 파일의 줄 텍스트가 아니라 파싱된 필드 목록입니다. 같은 dialect(`delimiter`, `escapechar` 등)의 `csv.writer`로 다시 쓰면 필드 값은 그대로 왕복하지만, 따옴표나 escape 같은 표기는 원본과 다를 수 있습니다. 문서에 이 점을 적습니다.

## 검증 기준

- 성공, `RowError`, `ColumnError` 레코드에서 검증기 적용 전 원문 반환
- 앞쪽 행 Pattern이나 컬럼 Pattern이 값을 바꿔도 원문 유지
- 반환값을 바꿔도 다음 `raw()` 결과에 영향 없음
- `offset` 건너뜀, `header()` 레코드 미반영
- 첫 읽기 전, 파일 끝, limit 도달, 파싱 오류, `close()`, 재`open()` 후 `None`
- `row()` 반복에서 실패 후 다음 레코드로 계속 진행
- `rows()` 순회 중 검증 예외 발생 시 실패 레코드 반환
- 같은 dialect로 다시 쓰고 읽었을 때 필드 값 왕복(구분자, 인용 개행, escape 문자 포함)
- `raw()`를 쓰지 않을 때 기존 동작 유지

검증 데이터는 비민감 합성 CSV를 사용합니다.
