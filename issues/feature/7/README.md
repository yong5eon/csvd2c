## 준비 현황

- 작업 트리에 기존 변경이 없는 상태에서 로컬 `master` 기준으로 `feature/7` 브랜치를 생성하고 전환했습니다.
- 이슈와 기존 검증 흐름을 분석하고, 후속 요청의 `__call__` 계약 변경과 행·라인·열 정보 전달을 요구사항 명세에 반영했습니다.
- 구현·검증 완료. 전체 테스트 124개가 통과했고 신규 타입 진단은 없습니다. 커밋·푸시·병합은 수행하지 않았습니다.
- 검증 실패는 예외로 알립니다. 공통 `Error(Exception)`를 행 Error `(message, row, value)`, 열 Error `(message, row, column, value)`가 상속합니다. Pattern의 `error=`와 호출형 Error 처리기는 제거했으며 기록·복구·건너뛰기는 호출자가 `try`/`except`로 처리합니다.
- 원본값은 실패한 Pattern에 들어온 값입니다. 파일 최초 값·체인 시작 값의 별도 보존은 요구하지 않습니다. 열 검증은 행 검증 완료 후 변경된 행을 기준으로 합니다.
- 행 Pattern·Validator는 `(List[str], int) -> List[str]`, 열 Pattern·Validator는 `(str, int, Union[int, str]) -> str` 호출 계약입니다.
- 최상위 공통 Error는 `src/Error.py`에 있으며 행·열 Error가 모두 상속합니다. 위치를 식별할 수 없는 실패는 공통 Error를 사용합니다.
- 원본 이슈에 댓글은 없습니다.

## 원본 이슈 본문

원본 본문은 아래에 그대로 보존합니다.

````markdown
## 목적

행과 열 검증 중 실패를 처리할 때 원본 맥락을 전달할 수 있도록 지원해 주세요.

핵심은 기존 `csvd2c.row.Error` 클래스와 `csvd2c.column.Error` 클래스를 활용하고, 검증 실패를 판단하는 Pattern이 해당 Error 구현에 맥락 정보를 전달할 수 있도록 지원하는 것입니다.

## 현재 계약과 부족한 점

- `row.Error.__call__(row: List[str]) -> List[str]`는 실패 행을 받아 대체 행을 반환하거나 예외를 발생시킵니다.
- `column.Error.__call__(col: str) -> str`는 실패 값을 받아 대체 값을 반환하거나 예외를 발생시킵니다.
- `Length`처럼 이미 Error 구현을 연결할 수 있는 Pattern이 있습니다.
- 현재 값만 전달하는 계약으로는 앞선 Pattern 적용 전 원본, 실패 원인과 컬럼 식별 정보를 함께 다루기 어렵습니다.

## 요구사항

### 기존 Error 클래스 활용

- 행 검증 실패 처리는 `row`의 `Error` 클래스를 활용합니다.
- 열 검증 실패 처리는 `column`의 `Error` 클래스를 활용합니다.
- 호출자가 Error 구현에서 오류 기록, 예외 발생 또는 명시적 값 복구를 선택할 수 있도록 합니다.
- 별도의 오류 처리 실행 계층이나 신규 예외 체계 도입 자체를 필수 구현으로 삼지 않습니다.

### Pattern의 맥락 정보 전달 지원

- 검증 실패를 판단하는 Pattern이 Error 구현으로 실패 원인과 원본 맥락을 전달할 수 있도록 지원합니다.
- 전달할 맥락에는 검증 전 원본 필드 배열, 열 실패 시 컬럼 인덱스·헤더가 있을 때 컬럼명·클린징 전 컬럼 원값을 포함합니다.
- Pattern 실패 시점의 처리 중 값과 검증 체인 적용 전 원본 값을 구분합니다. 앞선 Pattern이 값을 변경해도 원본 값을 그 변경값으로 대체하지 않습니다.
- 행 실패처럼 컬럼을 특정할 수 없는 경우 컬럼 정보가 없음을 명확하게 표현합니다.
- 원본 맥락의 확보·보존 책임과 Pattern에서 Error로 전달하는 계약을 정리합니다. 호출자가 검증 루프를 재구현하지 않고 CSV에 Validator를 직접 주입할 수 있어야 합니다.
- 이미 Error를 지원하는 Pattern은 기존 구조를 활용합니다. 직접 예외만 발생시키는 검증 Pattern은 필요한 연결을 보완합니다.
- 사용자 정의 행·열 Pattern도 같은 Error·맥락 전달 계약을 적용할 수 있도록 예시를 제공합니다.
- 실제 실패를 발생시키는 Pattern을 조사해 필요한 대상을 보완하며, 순수 변환 Pattern까지 일괄 확장하지 않습니다.

### 호환성과 실패 동작

- 기존 `row.Error`·`column.Error` 구현의 호출 계약과 호환성을 검토하고, 변경이 필요하면 영향과 사용법을 명시합니다.
- Error가 반환한 명시적 복구 값의 처리와 Error 미지정 시 기존 실패 동작을 유지합니다.
- Error 구현의 예외와 파일 기록 실패를 숨기거나 정상 값으로 바꾸지 않고 전파합니다.
- 논리 레코드 경계가 확보된 검증 실패 후 호출자가 다음 레코드를 읽을 수 있는 기존 동작을 유지합니다.
- CSV 파싱·디코딩 실패와 검증 실패를 구분합니다. 확보하지 못한 원문·위치를 추측하거나 재구성 문자열을 정확한 원문으로 표시하지 않습니다.

파일 경로·출력 형식·재처리 CLI는 호출자의 책임이며 이 요청에 포함하지 않습니다. 외부 프로젝트의 사용자 정의 Pattern을 임의로 수정하는 대신 적용 가능한 계약과 예시를 제공합니다.

## 검증 기준

- 행·열 검증 Pattern이 각각 기존 `row.Error`·`column.Error` 구현으로 실패를 전달하는지 확인
- 원본 행·컬럼 식별 정보·클린징 전 값·실패 원인의 전달 확인
- 앞선 Pattern의 값 변경 후에도 원본 맥락 보존 확인
- 헤더 없는 입력과 컬럼을 특정할 수 없는 행 실패의 표현 확인
- 기존 Error 지원 Pattern과 보완한 Pattern의 명시적 복구·예외 전파 확인
- 사용자 정의 행·열 Pattern의 맥락 전달 적용 예시 확인
- 인용 개행, 검증 실패 후 다음 레코드 읽기, Error의 파일 기록 실패 전파 확인
- 기존 Error 구현·정상 입력 반환값·Error 미지정 실패 동작의 호환성 확인

검증 데이터는 비민감 합성 CSV를 사용합니다.
````
