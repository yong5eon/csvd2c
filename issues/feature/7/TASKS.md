# 요구사항 분석과 명세 작성 결과

## 결과

[요구사항 명세](./REQUIREMENTS.md)에 기존 Error 활용, `__call__` 계약 변경, Pattern 입력값·라인 번호·열 식별자 전달과 예외 전파 요구를 정리했다.

후속 요청에 따라 열 식별자를 숫자 인덱스 또는 문자열 컬럼명인 `Union[int, str]`로 명세했다. 컬럼 값 자체의 `str` 계약은 유지한다.

Pattern의 데이터 검증 실패는 직접 `ValueError`를 발생시키는 대신 해당 행·열 Error의 `__call__`로 처리하도록 명세를 보완했다.

후속 확인에 따라 위 처리 방향을 모든 사용자 정의 Pattern의 강제 규칙으로 적용하지 않는다. Error 지정·예외 발생을 일괄 필수로 하지 않으며, 예외 타입과 입력 유지·기록·복구 여부는 사용하는 쪽에서 결정한다.

식별 불가능한 검증 실패를 위한 최상위 공통 Error는 `src/Error.py`에 정의하고, `src/row/Error.py`와 `src/column/Error.py`의 Error가 모두 이를 상속하도록 확정했다.

최종 사용자 확인에 따라 원본값은 해당 Pattern의 입력값이다. 파일 최초 값과 검증 체인 시작 값을 별도로 보존하지 않는다. 열 검증은 행 검증 완료 후 변경된 행을 기준으로 수행하고, 실패한 열 Pattern이 자신에게 들어온 값을 Error에 전달한다.

분석에서 기존 검증 Pattern이 이미 Error를 지원함을 확인했다. 앞선 Pattern의 변환값을 다음 Pattern에 전달하는 흐름은 유지하고, `IfLength`가 내부 Error의 `ValueError`를 재처리하는 동작은 보완한다.

관련 기존 테스트 63개가 통과했다. 이는 변경 전 동작 확인이며 새로운 API나 인수 기준의 통과를 의미하지 않는다. 명세 작성 단계에서는 제품 코드·사용 매뉴얼을 변경하지 않았다.
