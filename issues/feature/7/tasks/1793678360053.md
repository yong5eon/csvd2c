# 배포 패키지·타입 기준선·문서 예제 검증 중간 결과

작업 전용 격리 환경에서 편집 설치를 일반 wheel 설치로 바꿔 패키지 내보내기와 정적 import를 검증했다. 저장소 루트에서 다음 명령을 실행했다.

```shell
python -m pip install --force-reinstall .
python -m unittest discover -s tests
pyright --pythonpath <검증 환경의 Python> --pythonversion 3.9 src tests samples
```

- wheel 빌드·설치 성공. 전체 테스트 122개 중 행 Error가 입력 리스트를 변경하는 기존 회귀 테스트 1개 실패. 현재 Pattern 입력의 방어적 복사 보존이 필요하며 소스 수정·재설치 후 다시 검증해야 한다.
- `test_error_context.py`에 실제 파일 기록 실패 검증을 추가한 후 해당 파일의 10개 테스트 통과. 디렉터리를 로그 파일 대상으로 지정한 실제 `OSError`가 CSV 밖으로 전파되고 다음 `row()`가 정상 레코드를 읽는지 확인했다.
- Pyright 1.1.414의 전체 소스·테스트·샘플 진단은 변경 전 HEAD 추출본 28개, 현재 28개였다. 파일명·진단 규칙·메시지의 다중집합 비교에서 신규 진단 0개를 확인했다. 기존 Unicode 정규화 타입, 스트림 샘플 타입, 테스트 스트림 override 및 의도적으로 잘못된 인자를 사용하는 테스트 진단은 수정하지 않았다. 전체 타입 검사가 오류 없이 통과했다는 의미는 아니다.
- 루트 README·상세 매뉴얼의 Python 코드 블록 29개를 Python 3.9 문법으로 분석하고, 파일 입력을 요구하지 않는 독립 assertion 예제 10개를 실제 설치 패키지로 실행했다.
- 문서 22개의 상대 링크 144개와 이슈 문서의 개인 절대 경로 검사 통과. `git diff --check` 통과.

일반 wheel은 소스와 별도이므로 행 입력 복사 수정 후 재설치해야 한다. 최종 전체 테스트·타입 비교와 구현 종합 기록은 아직 남아 있다. 외부 Python 설치·사용자 편집기 환경은 변경하지 않았으며, 검증 환경과 기준선 추출본은 저장소 밖 임시 자료이다.
