# 호출 계약과 라인 정보를 반영한 요구사항 명세 작성

- 이슈 원문과 기존 Error·Pattern·Validator·CSV의 검증 흐름을 대조한 분석을 바탕으로 [REQUIREMENTS.md](../REQUIREMENTS.md)를 작성했다.
- 후속 사용자 요청에 따라 별도 `handle()` 제안은 채택하지 않고 `__call__` 계약 변경을 명세했다. 행 Error는 행·라인, 열 Error는 행·라인·열 정보를 받으며 원본과 실패 시점 값을 구분한다.
- 라인 번호 하나를 전달하며, 이전 설명의 기준인 실패 레코드의 마지막 물리 라인 번호를 명세했다. 정확한 오류 문자 위치로 표시하지 않는다.
- 앞선 분석에서 `Strip → Required`의 원본 공백 유실, 인용 개행 레코드 실패 후 다음 `row()` 읽기, `IfLength`의 내부 Error `ValueError` 복구 처리를 재현했다.
- 기존 테스트 `test_row_conditions.py`, `test_column_patterns.py`, `test_csv.py`를 `unittest`로 실행하여 63개 통과를 확인했다. 저장소 소스를 `importlib`로 로드한 메모리 내 보조 실행을 사용했으며 보존된 테스트 실행 스크립트는 없다.
- 첫 테스트 실행에서 외부 패키지의 site 초기화 오류가 출력되었다. 외부 환경은 수정하지 않고 `python -S`로 같은 63개 테스트를 다시 실행하여 통과를 확인했다. 변경된 API의 검증 결과는 아니다.
- README에 명세와 작업 기록 링크를 추가하고, 구현이 수행되지 않았음을 유지했다. 제품 API·동작은 변경하지 않아 사용 매뉴얼 갱신은 이번 단계에서 필요하지 않다.
- 다음 단계는 행 구조 변경 후 원본 컬럼 대응 기준과 병합 대상 확인, 구현 계획 작성이다. 미확정 사항을 임의로 확정하지 않았다.
