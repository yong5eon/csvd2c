# 이슈 분석과 요구사항 명세 작성

이슈 원문을 `src/CSV.py`의 현재 동작과 #10에서 바뀐 계약에 대조하여 [요구사항 명세](../REQUIREMENTS.md)를 작성했다.

## 분석 결과

- #10 이후 `header()`는 레코드를 읽지 않고, 헤더 검증기가 적용되면 `open()`이 헤더 레코드를 읽는다. 원문의 "`header()` 다음 레코드부터 센다"를 "`open()`이 읽은 헤더 다음 레코드부터 센다"로 바꿔 적용했다.
- `row()`와 `rows()`는 같은 `reader`를 공유하지만 읽은 레코드 수 등의 범위 상태는 없다. 범위 상태를 열린 파일 단위로 두어야 혼용·재호출에서 같은 결과를 얻는다.
- `csv.reader`의 `next()` 한 번이 인용 개행을 포함한 논리 레코드 1건이다.
- `rows()` 순회 중 검증 예외가 나면 Generator가 종료되므로, 검증 실패 후 계속 읽는 경우는 `row()` 반복이나 `rows()` 재호출이 된다.

## 결정 사항

- 사용자 요구: 범위는 `CSV` 생성자와 `open()` 두 곳에서만 제공한다.
- 사용자 결정: `open()`에서 생략하거나 `None`을 넘기면 #10과 같이 생성자 값을 사용한다. 생성자 `limit`을 `open()`에서 해제할 수 없는 제약을 명세에 남겼다.
- 사용자 결정: limit 구간의 파싱·디코딩 오류는 limit에 세지 않고 전파한다.
- offset 구간은 이슈의 "`row()`·`rows()`로 읽는 레코드만 센다"에 맞춰 첫 레코드 읽기 시점에 건너뛴다.
- `bool`은 개수를 뜻하지 않으므로 정수가 아닌 값으로 거부한다.
