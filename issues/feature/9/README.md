## 목적

`CSV`가 읽을 논리 레코드 범위를 offset·limit으로 지정할 수 있도록 지원해 주세요. 호출자가 레코드 수를 직접 세거나, 건너뛸 레코드를 빈 Validator로 읽어 버리는 우회 코드를 작성하지 않아도 되도록 하는 것이 목적입니다.

## 현재 동작과 문제

csvd2c 0.1.2에는 읽기 범위를 지정하는 기능이 없습니다. 파일의 일부 구간만 처리하려면 호출자가 다음과 같이 우회해야 합니다.

- 건너뛸 레코드를 검증하지 않으려고 `row(row=Validator(), cols={})`처럼 빈 Validator로 읽어 버립니다.
- 처리할 레코드 수를 호출자가 직접 세어 반복을 멈춥니다.

이 우회는 파일마다 반복되며 csvd2c 사용 방식과도 맞지 않습니다.

## 요구사항

### 주입 위치

- 생성자와 `open()`에서 `offset`, `limit`을 받습니다.
- 생성자 값을 기본으로 사용하고, `open()`에 값을 넘기면 그 파일을 여는 동안에만 해당 값을 적용합니다. 이 규칙은 헤더 검증기 주입 이슈(#10)와 동일하게 적용합니다.
- `offset` 기본값은 0, `limit` 기본값은 제한 없음입니다. 0 이상의 정수만 허용하고 그 외 값은 거부합니다.

### 범위 계산

- `row()`와 `rows()`로 읽는 레코드만 셉니다. `header()`로 읽은 레코드는 세지 않습니다.
- csvd2c가 파일에 헤더가 있는지 판단하지 않습니다. 헤더가 있는 파일은 호출자가 `header()`를 먼저 부르므로 헤더 다음 레코드부터 세고, 헤더가 없는 파일은 첫 레코드부터 셉니다.
- 단위는 물리 행이 아니라 논리 레코드입니다. 인용 개행이 있는 레코드도 1건입니다.
- `open()`할 때마다 처음부터 다시 셉니다.

### offset 구간

- offset으로 건너뛰는 레코드에는 행·컬럼 Validator를 적용하지 않습니다.
- 건너뛰는 중 발생한 CSV 파싱·디코딩 오류는 숨기지 않고 그대로 전파합니다. 레코드 경계를 확정할 수 없기 때문입니다.

### limit 구간

- 검증에 실패한 레코드도 limit의 1건으로 셉니다. limit은 성공 건수가 아니라 처리한 레코드 수입니다.
- limit을 채우면 다음 `row()` 호출과 `rows()` 순회는 `StopIteration`으로 종료하며, 다음 레코드를 읽지 않습니다. limit 바로 다음 레코드에 파싱 오류가 있어도 발생시키지 않습니다.
- `limit=0`이면 레코드를 읽지 않고 종료합니다.

### row()와 rows()의 동작

- 검증 실패 레코드를 기록하고 계속 읽는 호출자는 `row()`를 반복 호출합니다. 범위는 이 사용 방식에도 적용되어야 합니다.
- `row()`와 `rows()`를 섞어 호출해도 같은 범위 상태를 공유합니다.
- 범위를 지정하지 않으면 기존 동작과 결과가 같아야 합니다.

## 검증 기준

- 생성자 기본값과 `open()` 지정값의 적용·재오픈 시 초기화
- `header()` 호출 여부와 관계없는 범위 계산
- 인용 개행 레코드를 1건으로 계산
- offset 구간의 Validator 미적용과 파싱 오류 전파
- 검증 실패 레코드의 limit 포함
- limit 도달 후 다음 레코드를 읽지 않음, `limit=0`
- `row()` 반복·`rows()` 순회·혼용에서 같은 결과
- 음수·정수가 아닌 값 거부
- 범위 미지정 시 기존 동작 유지

검증 데이터는 비민감 합성 CSV를 사용합니다.
