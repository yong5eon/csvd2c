# 읽기 범위 offset·limit 요구사항

## 목적과 근거

[이슈 원문과 작업 메타데이터](./README.md)를 기준으로, 호출자가 레코드 수를 직접 세거나 건너뛸 레코드를 빈 Validator로 읽는 우회 코드 없이 `CSV`가 읽을 논리 레코드 범위를 지정할 수 있게 한다.

사용자 요구와 결정에 따라 다음을 적용한다.

| 항목 | 이슈 원문 | 적용 결정 |
| --- | --- | --- |
| 제공 위치 | 생성자와 `open()` | `CSV` 생성자와 `open()` 두 곳에서만 제공한다. `row()`·`rows()` 등 다른 메서드에는 범위 인자를 추가하지 않는다(사용자 요구) |
| `open()`의 생략·`None` | #10과 동일한 규칙 | #10과 같이 생략하거나 `None`을 넘기면 생성자 값을 사용한다. 따라서 생성자에서 지정한 `limit`을 `open()`에서 해제할 수 없다(사용자 결정) |
| 범위 시작점 | `header()`로 읽은 레코드 다음부터 | #10 이후 `header()`는 레코드를 읽지 않는다. `open()`이 헤더 검증기로 읽은 헤더 레코드는 세지 않고 그 다음 레코드부터 센다 |
| limit 구간의 파싱·디코딩 오류 | 언급 없음 | 레코드를 받지 못했으므로 limit에 세지 않고 오류만 전파한다(사용자 결정) |

## 현재 구조 분석

- [CSV](../../../src/CSV.py)는 생성자에서 `header`, `row`, `column` 검증기를 받고, `open(path, mode, header)`는 헤더 검증기만 이번 오픈에 한해 덮어쓴다. `None`이면 생성자 값을 사용한다.
- 헤더 검증기가 적용되면 `open()`이 첫 레코드를 읽어 검증한다. 적용되지 않으면 `open()`은 레코드를 읽지 않는다. `header()`는 레코드를 읽지 않고 저장된 헤더를 반환한다.
- `row()`는 `next(reader)`로 레코드 하나를 읽은 뒤 검증하고, 검증 실패 예외는 레코드를 소비한 뒤 전파된다. 파일 끝에서는 `StopIteration`이 그대로 전파된다.
- `rows()`는 같은 `reader`를 순회하는 Generator를 반환한다. 순회 중 검증 예외가 나면 Generator가 종료되므로, 계속 읽으려면 `row()`를 반복 호출하거나 `rows()`를 다시 호출한다.
- `row()`와 `rows()`는 같은 `reader`를 공유하므로 섞어 호출하면 이어서 읽는다. 읽은 레코드 수나 범위 상태는 없다.
- `csv.reader`는 인용 필드 안의 개행을 하나의 레코드로 반환하므로, `next(reader)` 한 번이 논리 레코드 1건이다.
- `close()`와 `open()`은 `reader`, `text`, `header_data`를 초기화한다.

## 포함 범위

### R1. 제공 위치와 값

- `CSV` 생성자에 `offset`, `limit` 키워드 인자를 추가한다. 기본값은 `offset=0`, `limit=None`(제한 없음)이다.
- `open()`에 `offset`, `limit` 인자를 추가한다. 기본값은 `None`이다.
- `row()`, `rows()`, `header()` 등 다른 메서드에는 범위 인자를 추가하지 않는다.
- 허용 값은 0 이상의 정수다. 생성자의 `limit`과 `open()`의 두 인자는 `None`도 허용한다.
- 정수가 아닌 값은 `TypeError`, 음수는 `ValueError`로 거부한다. `bool`은 `int`의 하위 타입이지만 개수를 뜻하지 않으므로 정수가 아닌 값으로 거부한다.
- 생성자 값은 생성자에서, `open()` 값은 파일을 열기 전에 검사한다.

### R2. 생성자 기본값과 open() 덮어쓰기

- 생성자 값을 기본으로 사용한다.
- `open()`에 값을 넘기면 그 파일을 여는 동안에만 적용한다. `offset`과 `limit`은 각각 독립적으로 덮어쓴다.
- `open()`에서 생략하거나 `None`을 넘기면 해당 인자는 생성자 값을 사용한다.
- 파일을 닫은 뒤 다시 열면 그 `open()` 호출의 인자와 생성자 값으로 다시 정한다. 이전 `open()`의 값은 남지 않는다.

### R3. 범위 계산

- `row()`와 `rows()`가 읽는 논리 레코드만 센다. `open()`이 헤더 검증기로 읽은 헤더 레코드는 세지 않는다.
- csvd2c는 파일에 헤더가 있는지 판단하지 않는다. 헤더 검증기가 적용되면 헤더 다음 레코드부터, 적용되지 않으면 첫 레코드부터 센다.
- 레코드 위치는 0부터 센다. `offset=0`은 범위 계산의 첫 레코드부터 읽고, `offset=n`은 앞의 n건을 건너뛴다.
- 인용 개행을 포함한 레코드도 1건이다.
- `open()`할 때마다 처음부터 다시 센다.

헤더가 있는 다음 파일을 헤더 검증기와 함께 열면 헤더 행은 세지 않으므로 레코드 위치는 다음과 같다.

| 파일 행 | 내용 | 레코드 위치 |
| --- | --- | --- |
| 1 | `name,age` | 헤더(세지 않음) |
| 2 | `kim,10` | 0 |
| 3 | `lee,20` | 1 |

`offset=0`이면 `kim,10`부터, `offset=1, limit=1`이면 `lee,20` 한 건만 읽는다. 헤더 검증기 없이 열면 `name,age`가 위치 0이다.

### R4. offset 구간

- offset으로 건너뛰는 레코드는 첫 `row()` 또는 `rows()`의 레코드 읽기 시점에 읽어서 버린다. `open()`은 offset 구간을 읽지 않는다.
- 건너뛰는 레코드에는 행·열 Validator를 적용하지 않는다.
- 건너뛰는 중 발생한 CSV 파싱·디코딩 오류는 숨기지 않고 그대로 전파한다.
- 건너뛰는 중 파일 끝에 도달하면 해당 `row()` 호출은 `StopIteration`, `rows()` 순회는 종료한다.

### R5. limit 구간

- offset 이후 `row()`·`rows()`가 읽은 레코드를 limit의 1건으로 센다. 행·열 검증에 실패한 레코드도 1건으로 센다.
- CSV 파싱·디코딩 오류로 레코드를 받지 못한 경우는 세지 않고 오류를 전파한다.
- limit을 채우면 다음 `row()` 호출은 `StopIteration`을 발생시키고 `rows()` 순회는 종료한다. 이때 다음 레코드를 읽지 않으므로 그 레코드의 파싱 오류도 발생하지 않는다.
- `limit=0`이면 레코드를 읽지 않고 종료한다. offset 구간도 읽지 않는다.

### R6. row()와 rows()의 상태 공유

- 범위 상태(남은 offset, 읽은 레코드 수)는 열린 파일 단위로 하나이며 `row()`와 `rows()`가 공유한다.
- `row()` 반복, `rows()` 순회, 두 방식의 혼용, 검증 실패 후 `rows()` 재호출에서 같은 범위의 레코드를 얻는다.

### R7. 기존 동작 유지

- 범위를 지정하지 않으면(`offset=0`, `limit=None`) 기존 동작과 결과가 같다.
- 기존 인자의 이름·순서·기본값, 헤더 검증, 행·열 검증과 오류 계약은 바꾸지 않는다. 새 인자는 키워드 인자로 추가한다.

### R8. 문서

- 한국어·영어 상세 매뉴얼과 루트 README에서 범위 지정 방법, 생성자·`open()` 적용 규칙, 헤더와의 관계, 검증 실패 레코드의 계산, `open()`에서 생성자 `limit`을 해제할 수 없는 제약을 필요한 범위에서 반영한다.

## 제외 범위

- `row()`·`rows()` 등 생성자와 `open()` 이외의 범위 지정
- `open()`에서 생성자 `limit`을 해제하는 방법
- 물리 행 기준 범위, 성공 건수 기준 limit
- 헤더 여부 자동 판단
