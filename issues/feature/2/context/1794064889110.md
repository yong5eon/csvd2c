# Iterator 설계 근거

## 상황과 목표

[이슈 요구사항](../REQUIREMENTS.md)은 `next(csv)` 지원과 `row()`·`rows()`의 cursor·검증 동작 일치를 요청한다. 검토 사항으로 닫힌 파일, 검증 실패 후 다음 호출, Validator 설정을 지정했으며 파싱·디코딩 오류 복구는 별도 범위로 둔다.

## 근거와 결정

- `src/CSV.py`의 `row()`와 `rows()`는 공통 `read_record()`·`validate()` 경로를 사용한다. offset·limit과 원문 저장은 `read_record()`가 담당하며 검증 전 레코드가 소비된다.
- `rows()`가 반환하는 generator는 EOF를 정상 종료하고 Validator가 일으킨 `StopIteration`을 Python generator 규칙에 따라 `RuntimeError`로 노출한다.
- `close()`는 reader를 초기화하며 `open()`은 새 reader와 읽기 범위를 설정한다. `row()`와 `rows()`는 닫힌 상태에서 `RuntimeError`를 발생시킨다.

`iter(csv)`는 `self`를 반환하고 `__next__()`는 `next(self.rows())`로 기존 generator 흐름을 재사용하도록 계획했다. 이 방식은 다음 호출 때마다 현재 reader와 기본 Validator를 선택하여, 별도 cursor 상태나 읽기·검증 로직 중복 없이 기존 API와 위치를 공유한다. `row()` 이름 변경은 명시적으로 확정되지 않아 하지 않는다.
