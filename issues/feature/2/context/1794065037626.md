# Iterator 구현과 검증 결과

## 상황과 목표

[설계 근거](./1794064889110.md)와 [계획](../PLAN.md)에 따라 iterator를 기존 단일 행·generator 경로에 연결하고 공개 사용법을 확인했다.

## 구현 결정과 영향

- `src/CSV.py`의 `__iter__()`는 `self`를 반환하고, `__next__()`는 `next(self.rows())`를 사용한다. `row()`의 읽기·검증 로직을 복제하지 않아 offset, limit, 생성자 Validator, EOF와 Validator-raised `StopIteration` 동작을 `rows()`와 공유한다.
- 새 별도 iterator 상태는 두지 않는다. 따라서 닫힌 파일에서 읽으면 `RuntimeError`가 발생하고 같은 `CSV`를 다시 열면 새 reader에서 시작한다. 검증 오류는 실패 레코드를 소비한 상태로 전파되며 다음 호출로 이어진다.
- `row()`의 이름·계약을 유지하고 파싱·디코딩 오류 이후 안전한 재개 기능은 추가하지 않았다.
- 양언어 매뉴얼·빠른 시작에서 `next(csv)`와 반복문을 안내하고, 거부 레코드 예제를 새 API로 변경했다.
